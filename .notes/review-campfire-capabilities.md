# Review: campfire-capabilities

Whoever addresses an item deletes it. A group whose items are all gone is deleted too.

Paths are relative to `source/crates/campfire-capabilities/src/` unless they name a crate. Groups are named after the root cause their items share, and sorted by severity and benefit across the whole crate: wrong behavior first, then untrusted-data robustness, then structure, then cleanup. An item marked **(bug)** was confirmed against the code: the behavior is wrong today.

Fix the root cause of a group, not its items one by one. Most groups give the structural target first, and their items are the places that target removes.

## 3. Snapshot decode accepts state that the code then trusts

A snapshot is untrusted data. Some components validate in their `Deserialize` (`Meter`, `Experience`, `Modifiers`). Others derive `Deserialize` and validate part of their state in `SimComponent::check`, and the rest not at all. Code then indexes, binary-searches or does arithmetic on that state.

Target: a type's own invariants (sorted, bounded, in range) are kept by its `Deserialize`, so a decoded value is always valid. `check` keeps only what needs the world (book references, team counts). The repeated `<= Tick::LIMIT` test (in about fifteen `check` bodies: `actions/action_slots.rs`, `mode/timers.rs`, `combat/respawn.rs`, `orders/next_think.rs`, `navigation/route.rs`, `units/lifespan.rs`, `production/train_queue.rs`, `stats/modifier_clocks.rs`, ...) becomes one bounded decode: a stored-tick type, or `Tick`'s `Deserialize` in `campfire-common/src/tick.rs`, rejects a tick past `Tick::LIMIT`. Then no `check` can forget it.

- [ ] `actions/action_slots.rs:761-851` (`check`) with `actions/slot_kinds.rs` (`ranks`, `level_of`, `first_rank`, all `self.0[kind.index()]`): `check` does not validate `slot.kind` against the mode's `SlotKinds`, that the slots are sorted by kind, or that `slot.rank` is within the kind's ranks. An out-of-range kind panics in `SlotKinds`. Unsorted kinds break `partition_point` in `insert` and `first_of`. `ActionSlots::new` is `pub` and guards the sort only with `debug_assert!` (`:249`). Target: the decode rejects unsorted kinds, and `check` rejects a kind or rank the mode does not have.
- [ ] `combat/recent_attackers.rs:15,49`: `RecentAttackers` derives a transparent `Deserialize`, and `check` tests only the ticks. `record` binary-searches by `source`, so an unsorted or repeated list makes it miss entries and insert duplicates. Then the assist list is wrong or names a unit twice. Target: the decode rejects a list that is not strictly ascending by `source`, as `Experience`'s does.
- [ ] **(bug)** `stats/meter.rs:9-12,41-43,90-98,101-123`: the field doc says that `carry` is "0 while full or empty", but `fill` and `take` reach full and empty without a reset. Only `regen`, `add` and `set_max` reset it. The decode accepts any `carry`, and `Pools::check` (`stats/pools.rs:116-124`) returns `true`. A forged `carry >= hz` adds more than `per_second` over `hz` ticks. Target: one private step after each write resets `carry` at either end, so the invariant holds. Then `Pools::check` rejects `carry >= hz` (it has the `TickRate`) and a nonzero `carry` at either end. The reset must come first: a check alone would reject snapshots that the live code makes today.
- [ ] `vision/reveals.rs:45`: `Reveals::check` bounds `radius` and `team` but not `Reveal::last`. It is the one tick-holding state without the bound. The bounded tick decode above covers it.

## 4. Data is checked, then read back with `expect`

The load checks a fact and keeps the unchecked shape, so later code asserts what the check proved. The shape does not show the invariant, and a second caller can skip the check. Target: the check returns the narrower type (parse, don't validate), and later code matches on it.

- [ ] `actions/action_parts.rs:60-100` (`ActionParts::of`): `rate`, `damage`, `damage_kind` (attack), `unit_type` (train or build), and `resource`, `take`, `bounce` (gather) are `Option`s in a flat 32-field `ActionData`. `ActionDataField::misused` checks them, then seven `expect("the load checked ..")` read them back. Target: the load check makes the per-kind payload (a `KindData` per `ActionKind`), and `ActionParts` matches on it.
- [ ] `actions/gather_spec.rs` (`take: u32`): the data holds `NonZeroU32`, and `ActionParts` drops it with `.get()`. Target: `GatherSpec` keeps the `NonZeroU32`.
- [ ] `mode/map_data.rs:154-195` (`MapData::check_walkable`, `pub`): it resolves again what `ModeMap::resolve` already resolved (walls, pathing, every `MapPoint::position`, placed units, markers), with `expect("the book build checked the map")` on each. A call on a map that was not resolved first panics on untrusted data. `mode/mode_map.rs:193-206` does the same for a marker region: `region.holds(..)` is checked, then `corner.position().expect(..)` builds the `Region`. Target: `resolve` returns the resolved `ModeMap` with the positions and regions in it, and the walkable check takes that `ModeMap`.
- [ ] `mode/choice_book.rs:81` with `mode/mode_api.rs:549`: `ChoiceBook::chosen` checks that every entry is `Some` and returns `&[Option<Offer>]`. Its only caller calls `expect` on each entry. Target: return the `Offer`s.
- [ ] `production/build_specs.rs:14-36,63-72`: `Style` and the rates run are separate fields. `Style::Builders` with no rates (`rate` underflows on `len() - 1`) and `Alone` or `Builder` with rates can both exist. Target: `Style::Builders(rates)`.
- [ ] `scripts/state_decl/mod.rs:15-18`: `StateDecl { kind, initial }` stores the type twice. `initial.kind()` gives it, and `units/unit_state_book.rs:76` compares the two. Target: hold `initial` only, and derive `kind()`.
- [ ] Rank is a raw `u8` (64 signatures) where 0 means "not learned" on a slot and is invalid on a rule. `Action::values` and `resource_cost` (`actions/action.rs:100-110`) compute `rank - 1` and need a `has_rank` guard first. `charge_rule`, `channel_rule` and `toggle_rule` (`:78-96`) repeat that guard. `Action::arms` (`:127`) tests `rank > 0`. `Ranked::get` (`values/ranked.rs:31-37`) returns `None` for rank 0 per rank, but `Some` for `Ranked::One`. `Ranked::at` is `get(..).copied()` under a second name. Target: a `Rank(NonZeroU8)` for the rules, and `Option<Rank>` on a slot. Then `values(rank)` is total, `values_at` replaces the three `*_rule` copies, `Ranked::get(Rank)` has one answer, and `at` goes away.
- [ ] `values/share.rs:7-12`: `Share { parts, whole }` derives `PartialEq`, so equal values compare unequal (`"0.5"` and `"0.50"`, `"1.0"` and `Share::ALL`). Only `items/shop_data.rs` uses it today, and nothing compares it. Target: one fixed denominator (billionths in a `u32`), so equality is by value and the pair goes away.
- [ ] `values/stat.rs:11-16,52-58`: `Stat::Declared(DeclaredName)` is a public variant. `Stat::Declared("move_speed")` is a second form of `Stat::Engine(MoveSpeed)`, and `Ord` and `==` treat the two as different. Only `Stat::named` and `Deserialize` normalize. Target: the declared variant can be built only through the normalizing path.
- [ ] `areas/area_spec.rs` (`AreaSpec::of` returns `Option` for "time does not fit in ticks"), against `ActionParts::of` and `RankValues::all` (return `Result<_, ActionError::TimeTooLarge>`). Same condition, two shapes. Target: one load-time tick conversion error, and both return `Result`.
- [ ] `values/bounds.rs:106-122`, `values/speed.rs:27-37`, `units/collision_data.rs:33-47`: three hand-written "Scalar to `Num`, error on overflow" conversions with different messages, beside the shared `Scalar::num` and `checked` (`values/scalar.rs:30,57`). Target: the shared conversion.

## 5. Sim state is marked changed when it did not change

`campfire-sim` writes a resource or component into a delta snapshot when its `last_changed` is newer than the last copy (`campfire-sim/src/state_registry/mod.rs:612-614,676-678`). Each `DerefMut` on a `Mut` marks a change, so a write of the same value, or a `&mut` access that writes nothing, makes the delta larger. `stats/carried_mut.rs` already solves this: it reports `Touched` and marks only what changed. `slot_events` guards too (`mode/mod.rs:379`).

Target: every sim-state write goes through an owner that marks only a real change (the `CarriedMut` model, or `set_if_neq`). Add one match-test guard: a quiet tick (no input, no event) makes an empty delta. Then a new spurious write fails a test and is not found by review.

- [ ] `mode/calls.rs:113-122` (`Calls::commit`): after each successful mode call, `clone_from` writes into `ModeState` and `Choices`, whether or not the call changed them. Every `on_timer`, join, leave, death and level-up call marks both changed.
- [ ] `mode/mode_call.rs:38-40` (`ModeCall::begin`): `state.clear()` then `extend_from_slice` drops and clones again every `StateValue::Text` and `EntityList` allocation. It does this for each mode call, also for each `calc_damage` and `calc_heal` through `Calls::amount` (one per hit). Together with `commit`, the whole state is copied in and out of each call so that a failed call changes nothing. Target: the frame copies the state on the first write only, and `commit` writes back only a state that was written. This also fixes the item above.
- [ ] `mode/mod.rs:467`: `unit_deaths` calls `unanswered.extend(..)` on a `Mut<UnansweredDeaths>` on every tick that the hook exists, also with no deaths.
- [ ] `mode/mod.rs:527,533`: `level_ups` takes `resource_mut::<LevelUps>()` on every tick (a clear with no hook, a `mem::swap` into `due`).
- [ ] `orders/unit_order.rs:112,165` (`UnitOrder::apply`): `destination.set(to)` through `Mut` for every order, also when the value does not change (`Stop`, `Build`, `Gather` set `None` on a unit that is already at `None`). `Destination::walk_to` and `go` exist to prevent this, because an avatar's destination replicates.
- [ ] `combat/damage_pass.rs:264-268` (`deal`): `get_mut::<Pools>` and `take` for each damage, also when the amount after shields is 0.
## 6. Capability boundaries are not where the code is

`capability_set/mod.rs:96-135` declares the dependency of each capability. The code names other capabilities' types directly, outside those rows, and some core types hold state that belongs to a capability above them. Target: the dependency rows are true. A capability reaches another only through a registered seam (as `EffectQueues` does for listed effects). Each component sits in the module whose registry name it carries.

- [ ] `abilities/mod.rs:655-668` (`apply`): calls `Projectiles::deliver`, `Areas::deliver`, and `ItemBook` and `Inventory` directly. `Abilities` declares only `[Combat]`. Target: delivery by shape is registered per capability, like `EffectQueues`. The item-use spend is a hook that `Items` registers. The row then lists what the code uses.
- [ ] `actions/effect_lists.rs:244-324` (`queue`) with `:327-338` (`Does::capability`): `queue` handles `Spawn`, `Modifier` and `Purge` before `queues.of(does.capability())`. But `capability()` still maps `Modifier` and `Purge` to `Stats` (an arm that never runs, because no `Stats` queue is registered), and it panics for `Spawn`. Target: either split `Does` into pipeline effects and capability effects, with a total `capability()`, or register `Stats` and `Spawn` queues and remove the special cases.
- [ ] `navigation/mod.rs:852` (`dash_end`): builds `Delivered`, `Delivering { launch: None }`, `Reached::End` and `Hit` field by field from a `DashDelivery`. A new field of `Delivering` or `Hit` breaks the dash. Target: a constructor beside `DashDelivery` or `Delivered` takes the dash's end (unit, step, place).
- [ ] `units/dead.rs:8-16` (`"combat.dead"`), `units/forced_move.rs:12-25` (`"navigation.forced_move"`), `units/unit_row.rs:20-25` (`alive`, `targetable`, which "combat fills"), `stats/move_step.rs:34` (`"navigation.move_step"`, its `check` reads `Body`), `stats/life_pool.rs:5-9` (`LifePool`: what the mode's `[combat]` names, used by combat, mode, targets and production, never by stats). Target: each type goes to the capability that its name and its users give it. Or, if it is core state, the core documents it and names it `units.*`.
- [ ] `units/forced_move.rs:98-102` (`ForcedMove::blocks`): a function of `Option<&UnitTags>`, a `forced` flag and a `Block`, which reads nothing of `ForcedMove`. `abilities/mod.rs:188-190,296-297,372,500-501,558` spell `ForcedMove::blocks(tags, forced, Inventory::group(inventory, kind))` five times. Target: a method of `UnitTags` (or a small caster view) that takes the unit's parts and the slot kind, so callers do not compose `Inventory::group`.
- [ ] `stats/pool_id.rs:4,16`, `stats/pools.rs:8-10,21`, `stats/pool_cost.rs:4,8`: `Pools::LIMIT` is the id range of `PoolId` and the array length of `PoolCost`, but `Pools` defines it. This gives the cycles `pool_id`↔`pools` and `pool_cost`↔`pools`. Target: `PoolId::LIMIT`.
- [ ] `stats/modifier_spec.rs:12,42` imports `StateField` from `stats/modifier_handle.rs:40`: load-time data depends on the script handle. Two more `StateField` types, with different shapes, are in `units/unit_state_book.rs:20` and `mode/mode_schema.rs:30`. Target: the modifier's `StateField` in its own file on the spec side (or `ModifierStateField`), and the handle imports it.
- [ ] `stats/stats_api.rs:121-126` registers `OnAttack`, `OnAttackHit`, `OnDamageTaken`, `OnKill` and `OnTakedown` under stats. `scripts/hook.rs:163-170` gives them to `Capability::Combat`. See group 8 for the three lists of this set.
- [ ] `units/units_api.rs:1-142` (`UnitsApi`): registers only the `Pos` and `Vector` members, the position and vector API, which has no units. Target: a name and module for what it registers.
- [ ] `values/mod.rs:1-2`: the module doc says data-file value types, but the module also holds runtime geometry (`body_box`, `grid`, `polygon`, `shape`, `metric`, `fraction`, `squared_distance`), runtime indexes (`row_directory`, `name_list`, `name_table`) and runtime records (`hit`, `action_start`, `region`, `bounds`). Target: split by role (data values, geometry, runtime records), so the doc is true.

## 7. A resource's presence does not match its install

Some resources are always installed, but each read treats them as optional and returns silently when they are missing. This hides a missing install. Other resources are optional, but each read applies its own fallback. Target: a capability's resources are required (`Res<T>`, `resource::<T>()`) after the capability installs. `Option` stays only for what a mode can lack, and the install decides it once.

- [ ] `combat/damage_pass.rs:259`, `combat/mod.rs:435-437`, `stats/mod.rs:192,218`, `stats/refresh.rs:63`, `stats/held_pass.rs:63,77`, `stats/modifier_book.rs:187-203` (`has_way_in`): `ModifierBook` and `ParamBook` are always inserted by `Stats::install` (`stats/mod.rs:114-115`), and `Combat` requires `Stats`. Each site still uses `get_resource` or `Option<Res<_>>` and returns silently. Only `StatBook`, which a mode loads later, is optional.
- [ ] `values/bounds.rs:25-30` (`Bounds::of`, with a `Bounds::WORLD` fallback, called from eight sites) against `units/mod.rs:132` (`Metric`, always inserted). `navigation/mod.rs:124` inserts `Bounds::WORLD` separately. Two map-wide resources with two contracts. Target: the core installs `Bounds` like `Metric`.
- [ ] `navigation/mod.rs` (`make_room`, `open_cell`, `route_units`, `force_units`, `teleport`): each gets the `PathingGrid` and `RoutePlanner` options again. `abilities/mod.rs:679` tests `contains_resource::<ItemBook>()`. Target: one decision at install, read as required where the capability runs.

## 9. Hot paths pay for the rare case on every event

A hot path here runs per damage, per draw, per kill, or per script field read. Each item makes the common case pay for a case that seldom applies.

- [ ] `combat/modifier_hooks.rs:61-111` (`hear`): `damage(hit)` and `damage(taken)` (a `DamageHandle` with a `View` clone, boxed in a `Dynamic`) and `unit(..)` are evaluated as arguments before `run` looks for a modifier with the hook. `DamagePass::answer` fires `AttackHit` and `DamageTaken` for each landed damage. So each damage allocates, also in a match where no unit has an `on_damage_taken`. Target: `run` takes the argument as `impl FnOnce() -> Dynamic`, and calls it only when `heard` is not empty.

The same steps to begin a frame, call a hook within the budget, apply on success and record on failure are written in each system. Also, each capability applies its effects in a different shape. Target: one `ScriptBatch` (or `Calls`) method that runs a hook and does all of those steps, and one shape for `Effect::apply`.
