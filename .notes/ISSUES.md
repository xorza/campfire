# Issues

The issue log: every open problem of the project, under the step it waits for. The rules are in [AGENTS.md](../AGENTS.md#issue-log).

## Decide

- **Client.** The camera turns and zooms by keys only on a keypad, as Zero Hour's command map gives them (4 and 6, 8 and 2, 5), so a keyboard with no keypad, as a laptop's, turns it only by a middle-button drag, which a trackpad lacks. Options: keep the original's keys alone; add keys a keyboard with no keypad has.
- **Math.** `RngSource` keeps the sim's tick bookkeeping, the tick, the count of its starts and the debug check for a sequence opened twice in one tick, and `sim::SimRng` is a one-field wrapper of it. Keep it in `math`, as design 09 places the RNG, or move that bookkeeping into `SimRng` and keep only `Rng` and its streams in `math`.
- **Math.** Two exact ratio types of one kind live in `capabilities`' geometry and not in `math`: `Fraction`, a signed `i128` over `i128`, and `SquaredDistance`, a `U256` over a `u128`, each compared by its cross products. Move each to `math` as it is, or merge the two into one ratio type there.
- **Zero Hour.** The import writes W3D's materials into glTF's material model, which holds one pass, no ambient color and no fallback texture, so each part of a W3D material that glTF lacks is lost: the next two items, a missing texture and the ambient color, and the second pass under Research, are its cases. Options: an extension of glTF's material that the client draws; a material file of Campfire's beside each model; or glTF's model, as now, each loss decided alone.
- **Zero Hour.** A texture no archive holds leaves its triangles untextured in the import, where the game draws `MissingTexture`, a solid color of `0x7FFF00FF`: draw them as the game does, or untextured, as now.
- **Zero Hour.** The import ignores a vertex material's ambient color, as glTF's material has none: 336 vertex materials of converted models have one other than their diffuse color, which the game lights by the scene's ambient light. Options: a material file with the ambient color, which the client draws; or the diffuse color for both, as now.

## Research

- **Core.** The script view copies the whole match for each script batch: `ScriptBatch::run` reads every unit again and fills its row from all seven column sources, though few units change between two batches of one tick. `View::read` takes 14.2 % of a 3v3 match's time, in Think and the damage pass most.
- **Navigation.** The levels by size of B2 make the Collide stage slower for walkers of ordinary sizes, with no wide body present: on an M5, `integration/collision/spread` takes 83.0 µs against 42.3 µs with one level, `integration/collision/crowded` 215.9 µs against 171.8 µs, and `integration/collision/boxes` 639.4 µs against 516.6 µs. The scenes' walkers of 0.2 to 1.19 m spread over four levels of the broadphase, where one cell of 2.38 m held them all. With a 1,117 × 100 m box 2 m past the crowded scene, `integration/collision/bridge` takes 672.6 µs, and 516.5 µs with one level. The 3v3's server tick was not measured.
- **Navigation.** `integration/pathing_grid/enter` moves by 8 % with where the linker places `Regions::label`: the same machine code at offset 32 of its 64-byte line takes 131.7 µs, and at offset 48 121.4 µs, as its instructions a cycle fall from 4.49 to 4.23. A change anywhere in the crate can move it.
- **Package.** Only an avatar names its human text, its `name`; an action, a loadout's spell, a mode, a team and a choice have no message id, so a client can show none of their names, while the design says each name is a message id ([Human text](../docs/design/03-game-scripting.md#game-package)).
- **Package.** `mode_package::every_flaw_of_a_package_fails_its_load_with_its_own_problem` runs past the bound of 1 s for a test alone: on an i9-13980HX, 1.05 s with its 273 flaws, each a load of the 3v3's packages.
- **Runner.** `moba_abilities`' test units, and the client view tests' units, spawn by `world.spawn` with no unit type, where every unit a match makes spawns through `UnitCore` with its type, its tags and its script state: they are units no production path makes, and a system that filters units by the `UnitEntity` kind rather than by `UnitType` meets them. Which unit type of the 3v3 such a unit takes, so its tags change no filter the tests pin, is not known.
- **Runner.** `resume::the_3v3_match_resumes_from_each_checkpoint_to_the_same_hashes` runs past the bound of 1 s for a test alone: on an i9-13980HX, with `--test-threads 1`, 1.41 to 1.45 s at commit aa1e8aac, where `source/.config/nextest.toml` gives it 0.79 s on an M5.
- **Runner.** `proving_match::a_snapshot_of_drawn_values_restores_or_is_refused_and_never_panics` runs past the bound of 1 s for a test alone: on an i9-13980HX, with `--test-threads 1`, 1.00 to 1.03 s at commit aa1e8aac and after it. The five ticks after each restored draw take most of it, in the navigation's broadphase and collider.
- **Runner.** Two measurements of `integration/server_tick/worst_3v3` disagree: design 02 gives the 3v3's worst tick as 0.83 ms, and the later measurement for design 10's checkpoints gave 0.51 ms. Design 02's figure, and its mean of 114.4 µs from the same run, may not be the engine's now.
- **Script.** Scripts get no completion, signatures or descriptions in an editor. Rhai's VS Code extension highlights syntax only, and Rhai's language server, the one tool that reads a definition file such as `Engine::definitions` writes, is unpublished, marked experimental, and unchanged since October 2022.
- **Vision.** `Bitmap::set` is the largest function of `integration/server_tick/mean_3v3`, 6.9 % of it, for runs of one or two words a row; which of its parts costs that, the words' writes, the brush's mask or the record of each word set, is not known.
- **Zero Hour.** The import draws a mesh's first material pass and its first texture stage alone; 275 meshes of converted models have a second pass, which the game draws over the first.
- **Zero Hour.** The import makes a unit of every object a map places but a road's or bridge's end and a waypoint, whatever its template: the game spawns no object whose template no INI object names, adds props, optimized trees and, in multiplayer, fluff to the client alone, and spawns no shrub when trees are off (`GameLogic::startNewGame`).

## Ready

- **Actions.** **Plan: G1.** The projectile section's `gravity` is planned: no projectile falls, so no grenade arcs and no bullet drops.
- **Client.** **Plan: S2.** The client has no shop and no item keys: a player cannot buy, sell or use an item, which design 04's items give as orders.
- **Interaction.** **Plan: U1.** `interaction` is planned: no action of the `use` kind runs.
- **Runner.** The tests that pin a file write it again when `CAMPFIRE_BLESS` has any value, `0` and the empty text included: the runner's goldens (`harness/golden.rs:143`) and layouts (`tests/snapshot_layout.rs:67`), the script API reference (`campfire-capabilities/src/scripts/script_api/tests.rs:271`), the package directory's (`campfire-package/src/package_dir/tests.rs:367`) and the session log's format (`campfire-protocol/src/session_log/tests/format.rs:57`). A run with `CAMPFIRE_BLESS=0` passes and changes the pinned files.
