# Issues

The issue log: every open problem of the project, under the step it waits for. The rules are in [AGENTS.md](../AGENTS.md#issue-log).

## Decide

- **Client.** The camera turns and zooms by keys only on a keypad, as Zero Hour's command map gives them (4 and 6, 8 and 2, 5), so a keyboard with no keypad, as a laptop's, turns it only by a middle-button drag, which a trackpad lacks. Options: keep the original's keys alone; add keys a keyboard with no keypad has.
- **Math.** `RngSource` keeps the sim's tick bookkeeping, the tick, the count of its starts and the debug check for a sequence opened twice in one tick, and `sim::SimRng` is a one-field wrapper of it. Keep it in `math`, as design 09 places the RNG, or move that bookkeeping into `SimRng` and keep only `Rng` and its streams in `math`.
- **Math.** Two exact ratio types of one kind live in `capabilities`' geometry and not in `math`: `Fraction`, a signed `i128` over `i128`, and `SquaredDistance`, a `U256` over a `u128`, each compared by its cross products. Move each to `math` as it is, or merge the two into one ratio type there.
- **Zero Hour.** The import writes W3D's materials into glTF's material model, which holds one pass, no ambient color and no fallback texture, so each part of a W3D material that glTF lacks is lost: the next two items, a missing texture and the ambient color, and the second pass under Research, are its cases. Options: an extension of glTF's material that the client draws; a material file of Campfire's beside each model; or glTF's model, as now, each loss decided alone.
- **Zero Hour.** A texture no archive holds leaves its triangles untextured in the import, where the game draws `MissingTexture`, a solid color of `0x7FFF00FF`: draw them as the game does, or untextured, as now.
- **Zero Hour.** The import ignores a vertex material's ambient color, as glTF's material has none: 336 vertex materials of converted models have one other than their diffuse color, which the game lights by the scene's ambient light. Options: a material file with the ambient color, which the client draws; or the diffuse color for both, as now.

## Research

- **Client.** **Plan: I2.** The view tests' units spawn by `world.spawn` with `UnitEntity` and no unit type (`view/tests.rs:73`), where every unit a client receives holds its type, which the server sends with it: the view reads a unit's type as optional, `Option<&UnitType>` (`view/mod.rs:121`), and draws a unit of none, which no client meets. Which type such a unit takes, with the looks a test then needs, is not known.
- **Core.** **Plan: I1.** The script view copies the whole match for each script batch: `ScriptBatch::run` reads every unit again and fills its row from all seven column sources, though few units change between two batches of one tick. `View::read` takes 14.2 % of a 3v3 match's time, in Think and the damage pass most.
- **Core.** The prediction test, `release::tests::prediction_reads`, reads no access of an exclusive system, as Bevy gives one none, so it does not check what eight systems of a predicting client read: `Channels::predict_channels`, `Attacks::attack_events`, `DamagePass::run`, `ModifierIntervals::run_intervals`, `DeliveryHooks::end`, `Construction::start_builds`, `GatherLoop::run` and `Trains::finish_trains`, each through `QueryState`, `SystemState` or the world ([Replication audiences](../docs/design/14-replication-audiences.md), D12). The test names them in `EXCLUSIVE`, and fails on another.
- **Core.** Modules of one layer import each other both ways: `units` and `scripts`, and `units` and `players`, in layer 1; the layer test refuses only an import from a higher layer. What `units` takes from each, and whether that moves down or the two modules merge, is not known.
- **LAN check.** The check starts bot 1 again as soon as the server logs bot 1's first order, while the other bot's order of the same stamp may still be on its way, and it fails an order that misses its stamp tick. In CI run 37523961750 on Ubuntu, attempt 1, the server logged bot 1's order stamped 20 at 20:13:55.960; bot 0 sent its own at 55.971, and the server logged it at 56.086, 115 ms later, in tick 21; the new bot 1 process started in that window and joined at 56.108. On a runner of 4 cores, the new process's start shares them with the server and bot 0.
- **Navigation.** The levels by size of B2 make the Collide stage slower for walkers of ordinary sizes, with no wide body present: on an M5, `integration/collision/spread` takes 83.0 µs against 42.3 µs with one level, `integration/collision/crowded` 215.9 µs against 171.8 µs, and `integration/collision/boxes` 639.4 µs against 516.6 µs. The scenes' walkers of 0.2 to 1.19 m spread over four levels of the broadphase, where one cell of 2.38 m held them all. With a 1,117 × 100 m box 2 m past the crowded scene, `integration/collision/bridge` takes 672.6 µs, and 516.5 µs with one level. The 3v3's server tick was not measured.
- **Navigation.** `integration/pathing_grid/enter` moves by 8 % with where the linker places `Regions::label`: the same machine code at offset 32 of its 64-byte line takes 131.7 µs, and at offset 48 121.4 µs, as its instructions a cycle fall from 4.49 to 4.23. A change anywhere in the crate can move it.
- **Package.** Only an avatar names its human text, its `name`; an action, a loadout's spell, a mode, a team and a choice have no message id, so a client can show none of their names, while the design says each name is a message id ([Human text](../docs/design/03-game-scripting.md#game-package)).
- **Package.** **Plan: I4.** `mode_package::every_flaw_of_a_package_fails_its_load_with_its_own_problem` runs past the bound of 1 s for a test alone: on an i9-13980HX, 1.05 s with its 273 flaws, each a load of the 3v3's packages.
- **Quic.** The send queue keeps `quinn-proto`'s 1 MiB: the delay a full queue adds is its size over the connection's sending rate, tens of seconds at the minimum window, and Lightyear queues a reliable message again while its last copy still waits there. No scenario measures the largest burst one client receives, as at its join, or the delay the queue adds: the harness's link models delay and loss, not a rate.
- **Quic.** No bench measures the frame's two systems, the thread's batch, or the frame's waits for the mutex, nor a flood of handshakes from many addresses: what a handshake costs the thread under the mutex, and how long a batch of them holds the frame, which sets how many new connections a pass takes ([QUIC transport](../docs/design/15-quic-transport.md), D14). No pass bounds its new connections.
- **Quic.** The thread allocates under the mutex at times `quinn-proto`'s random numbers choose: 8 times at a connection's first key update, within its first 1,000 packets, and once when the packet numbers a connection received first hold three ranges, as each packet number a sender skips leaves a gap until the ranges before it are acknowledged. A read also allocates a new arena when `RecvBatch`'s ring comes back to an arena that a message slice Lightyear keeps still holds.
- **Runner.** **Plan: I4.** `resume::the_3v3_match_resumes_from_each_checkpoint_to_the_same_hashes` runs past the bound of 1 s for a test alone: on an i9-13980HX, with `--test-threads 1`, 1.41 to 1.45 s at commit aa1e8aac, where `source/.config/nextest.toml` gives it 0.79 s on an M5.
- **Runner.** **Plan: I4.** `proving_match::a_snapshot_of_drawn_values_restores_or_is_refused_and_never_panics` runs past the bound of 1 s for a test alone: on an i9-13980HX, with `--test-threads 1`, 1.00 to 1.03 s at commit aa1e8aac and after it. The five ticks after each restored draw take most of it, in the navigation's broadphase and collider.
- **Runner.** **Plan: I4.** `proving_match::a_snapshot_restores_and_a_flawed_one_never_panics` runs at the bound of 1 s for a test alone: on an i9-13980HX, with `--test-threads 1`, 1.11 s at commit e43f95af, and 0.87 s in a later run.
- **Runner.** Two measurements of `integration/server_tick/worst_3v3` disagree: design 02 gives the 3v3's worst tick as 0.83 ms, and the later measurement for design 10's checkpoints gave 0.51 ms. Design 02's figure, and its mean of 114.4 µs from the same run, may not be the engine's now.
- **Script.** Scripts get no completion, signatures or descriptions in an editor. Rhai's VS Code extension highlights syntax only, and Rhai's language server, the one tool that reads a definition file such as `Engine::definitions` writes, is unpublished, marked experimental, and unchanged since October 2022.
- **Stats.** **Plan: F16.** `Refresh::give_parts` gives a unit of a type that lacks them an empty `UnitStats`, which `Refresh::run` derives only for a unit with a `Level`, and `Refresh::regenerate` indexes that empty `UnitStats` by each pool's regeneration stat: a unit of a type with a pool and no `Level` panics there (`stats/refresh.rs:277`). Every unit a mode spawns holds a `Level`; whether a client can hold a unit's type and pools before its `Level` arrives is not known.
- **Vision.** `Bitmap::set` is the largest function of `integration/server_tick/mean_3v3`, 6.9 % of it, for runs of one or two words a row; which of its parts costs that, the words' writes, the brush's mask or the record of each word set, is not known.
- **Zero Hour.** The import draws a mesh's first material pass and its first texture stage alone; 275 meshes of converted models have a second pass, which the game draws over the first.
- **Zero Hour.** The import makes a unit of every object a map places but a road's or bridge's end and a waypoint, whatever its template: the game spawns no object whose template no INI object names, adds props, optimized trees and, in multiplayer, fluff to the client alone, and spawns no shrub when trees are off (`GameLogic::startNewGame`).

## Ready

- **Actions.** **Plan: G1.** The projectile section's `gravity` is planned: no projectile falls, so no grenade arcs and no bullet drops.
- **Client.** **Plan: S2.** The client has no shop and no item keys: a player cannot buy, sell or use an item, which design 04's items give as orders.
- **Core.** **Plan: F21.** `Hook::capability` (`scripts/hook.rs:153-178`), which the load check and the script API reference read, disagrees with the modules that record the hooks: it gives `OnHit` and `OnEnd` to `abilities`, which `deliveries` records, and `CalcDamage`, `CalcHeal` and `OnUnitDied` to `combat`, which the mode records.
- **Interaction.** **Plan: U1.** `interaction` is planned: no action of the `use` kind runs.
- **MOBA test content.** **Plan: I3.** The 3v3's `hero_died` gives assist gold to each of its `assisters` by the assister's `owner`, and an assister may be a unit no player owns, as a tower that struck the hero: the call fails with `Function not found: add_resource (Ctx, (), ...)`, changes nothing, and the kill gives no hero gold, the killer's own included.
- **Quic.** **Plan: N1.** No limit holds live connections or new handshakes for each address, where design 15's D13 bounds both by the session's seats for each IPv4 address or IPv6 /64, and `net` gives the endpoint no seat count ([QUIC transport](../docs/design/15-quic-transport.md), D13).
- **Quic.** **Plan: N2.** UPnP finds no router behind a host firewall that tracks connections when the router answers SSDP searches from a port other than 1900, as Omada's ER605 does: `igd-next` discovers by search alone, and the router's `NOTIFY` announcements, which the firewall lets in, go unread ([QUIC transport](../docs/design/15-quic-transport.md), D12).
- **Units.** **Plan: F16.** In a match with no `stats`, as the `ruled` test mode, a unit that is not a delivery and is restored or replicated never gets its `UnitTags`: only `stats` installs `Refresh::give_parts`, which returns early with no `StatBook`, while a spawned unit holds its type's tags. A block of its tags, its walk (`navigation/walking.rs:101`) and its script row (`units/unit_rows.rs:373`) then read none.
