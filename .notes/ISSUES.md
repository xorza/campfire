# Issues

The issue log: every open problem of the project, under the step it waits for. The rules are in [AGENTS.md](../AGENTS.md#issue-log).

## Decide

- **Lan-check.** Each `cargo drive run lan` writes a new folder of its logs and session log under `target/drive/lan-check/`, 6 to 14 MB each, and nothing removes one: 455 MB on 2026-10-20, after two days. ## Research

- **Combat.** A predicting client's strike, `Attacks::strike::<ClientForm>` (`combat/src/attacks.rs`), runs on no attacker: its query takes `&mut ClipShots`, a server part, so a predicted attack's windup stays due on the client, its cooldown is never predicted, and only the server's state ends it.
- **Import.** The imported package's `data/mode.toml` and `manifest.toml` come from `format!` templates (`import/src/zero_hour/rules_package.rs`, `mode_data` and `mode_manifest`), and its `data/units.toml` from structs that mirror the engine's sections, so a key the engine renames shows only as the import's own load of what it wrote fails.
- **Mode.** A kill's bounty (`mode/src/bounty_book.rs`, `Bounty::pay`) pays for a victim that is a site under construction, where Zero Hour's `Player::doBountyForKill` pays none for a victim `UNDER_CONSTRUCTION`; it shows once a script raises a Zero Hour player's share, as the Cash Bounty power would.
- **Navigation.** `Routing::route_units` (`navigation/src/routing.rs`) reads the change ticks of every walker's `Destination` and `Route` in each tick to find the walkers whose destination or route changed, as the many writers of `Destination` across the capabilities push no walker into an index.
- **Net.** The LAN check failed once in CI on macOS after the server's restart: a bot at its tick 299 sent an order stamped 300 while the server ran tick 303, so the server applied the two inputs stamped 300 in ticks 301 and 303 with no catch-up frame logged, and the check counts each a failure (run 39052741501, commit `f3ad15c8`).
- **Net-packets.** `PlainEstablishment::challenge` is `unreachable!` (`net-packets/src/plain_establishment.rs`): `Establish` asks every establishment for a path challenge, which the endpoint asks only of a peer routed by its connection ID, and a plain establishment routes none so.
- **Net-stack.** No bench loads an endpoint's pass with many links, nor with a flood of handshakes from many addresses: what a pass costs under its runtime's mutex, and how long it holds the frame, is not known, and no pass bounds the new links it takes.
- **Net-stack.** No scenario measures the largest burst one client receives, as at its join, nor the delay a link's send budget adds to it: the network harness's links model delay and loss, not a rate.
- **Release.** A test helper that changes a book in place, as `Units::give_type`, `Stats::give_type_stats` and `Actions::push` do, makes no check that `Book::load_into` makes: once a test match's first tick installs its systems, a change of a fact an install reads, as a turret, a channel or an interval, leaves the match without the passes of that feature, and nothing panics.
- **Runner.** `match_3v3::scripted_match::a_3v3_match_replays_to_the_same_hashes` runs past the 15 s that `source/.config/nextest.toml` gives a scripted match: on an i9-13980HX, alone, with `--test-threads 1`, 16.7 s at commit f16bca40, and 18.5 s with the architecture redesign over it, uncommitted.
- **Runner.** `resume::the_3v3_match_resumes_from_each_checkpoint_to_the_same_hashes` runs past the bound of 1 s for a test alone: on an i9-13980HX, with `--test-threads 1`, 1.86 s at commit f16bca40, and 2.02 s with the architecture redesign over it, uncommitted; at commit 3e7a72a0 its profile was flat, no function above 3 % at 20 kHz, and the cost a resume from each checkpoint, each a replay of the log to it.
- **Runner.** `proving_match::a_snapshot_of_drawn_values_restores_or_is_refused_and_never_panics` runs past the bound of 1 s for a test alone: on an i9-13980HX, with `--test-threads 1`, 1.95 s at commit f16bca40, and 2.68 s with the architecture redesign over it, uncommitted; at commit 3e7a72a0 its profile was flat, no function above 7 %, spread over restores, archetype moves, Rhai calls and movement, and the cost the sweep's size: each state type 16 draws, each restored draw 5 ticks.
- **Runner.** `proving_match::a_snapshot_restores_and_a_flawed_one_never_panics` runs past the bound of 1 s for a test alone: on an i9-13980HX, with `--test-threads 1`, 1.14 s at commit f16bca40, and 1.04 s with the architecture redesign over it, uncommitted: a restore for each byte of the snapshot, and 5 ticks after each one that restores.
- **Script.** A form that returns a list of names, as `unit.queue` and `ctx.map.paths`, gives plain text with no name kind, so the load checks no literal that a script compares with an item of the list.
- **Stats.** A unit a predicting client predicts again, as its owner changes and `Unpredicted` goes (`net/src/sim_client/mod.rs`, `mark_unpredicted`), keeps the change ticks its parts had while hidden: a pass that visits what changed by those ticks, as `Holds::want_passives` and the stats refresh do, may pass over it until a part of it changes, where a pass over every unit takes it at once. Whether Lightyear's prediction writes the parts again as it starts is not known.
- **Verifier.** `binary::the_binary_logs_the_last_state_hash` (`verifier/tests/binary.rs`) and the harness's `verifier::a_matchs_journal_publishes_the_log_its_twin_of_no_journal_holds` pass nextest's 5 s timeout at times in a full run of the suite, as the old `drive.py check` ran it, on an i9-13980HX, and pass in 0.8 s together alone (commit `00c0fba2`).

## Ready

- **Benches.** Each of the 16 crates with a `[[bench]]` sets `[lib] bench = false`, which no command reads: the driver selects the bench targets alone, by `--bench '*'`.
- **Client.** A press drags past 4 pixels along either axis, a constant of the client's code (`client/src/press.rs`, `DRAG_PIXELS`), and the Zero Hour import does not read the game's `Mouse.ini` `DragTolerance`, the pixels within which a press of the game is still a click.
- **Import.** `MapFile` and `UnitsFile` name Zero Hour's files in `import` and Campfire's files in `package`: two types of one name (14-workspace-alignment.md, A type name that both sides declare keeps one meaning).
- **Mode.** A spatial map's height grid and `[ground]` load into its `MapBook`, and the sim reads neither: `MapBook::point` takes a spatial map's position as its point in space.
- **Net.** A client inserts its session's `OutView` as a resource as it answers an offer (`net/src/sim_client/mod.rs`, `answer_offer`), and no system reads that resource: the match takes the view from `MatchFacts`.
- **Net-endpoint.** The frame's send step wakes the endpoint's IO thread at every frame, whether or not it took a payload or moved a deadline (`net-endpoint/src/endpoint/mod.rs`, `Endpoint::send`): an idle server's IO thread wakes at its tick rate.
- **Net-messages.** The receive path passes `ParallelCommands` through `MessageReceiveCx`, the message receivers and the remote events (`message_plugin/mod.rs:287`, `message_receive_cx.rs:13`, `message_receiver/mod.rs:110`), though its systems iterate their links in order.
- **Net-stack.** No lane of `cargo drive` measures coverage, which `13-net-stack/testing.md` plans.
- **Protocol.** The session log's `Packet`, a player's signed inputs (`protocol/src/session_log/log_entries.rs`), has the name of the network stack's `Packet`, the payload of one datagram (14-workspace-alignment.md, A type name that both sides declare keeps one meaning).
- **Rules.** `citations` reads a decision's title from its bullet's first line alone (`test/rules/src/citations.rs`, `titles`), so a title that wraps to a second line cannot be cited.
- **Stats.** `modifier_clocks`'s `Clock` (`stats/src/modifiers/modifier_clocks.rs`) has the name of the network stack's `Clock`, the app's network clock (14-workspace-alignment.md, A type name that both sides declare keeps one meaning).
- **Store.** `latest_writer`'s `Slot` has the word that Names gives to a unit's slot (14-workspace-alignment.md, A type name that both sides declare keeps one meaning).
- **Verifier.** No log or replay starts from a checkpoint's `LogCarry` (`protocol/src/checkpoint/log_carry.rs`): the log builds, writes and compares the carry, and a verifier replays every log from tick 0, so a host that prunes its logs past a checkpoint leaves a segment nothing verifies, where designs 02 (Session log) and 05 (Checkpoints and results) plan a segment's verification from its checkpoint alone.
