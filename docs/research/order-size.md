# The size of an order to a group

Read on 23 October 2026: Campfire's order encoding and session terms, the client's log of a Zero Hour base start against the builder bot, GeneralsX's source, Spring's network messages and the SC2 replay tools' documentation.

- **Campfire's order holds its units' ids.** An order's payload is postcard bytes: the count of commands, the capability, the body's length, then the body, the units as a count and a varint for each stable id, and the directive (`Order::write_payload`). A move to a point of the Zero Hour map, two `Num`s of 24 fraction bits near 800 m, takes 10 bytes, so a move is 15 bytes besides its ids.
- **The LAN terms allow an input 64 bytes.** `InputRules::LAN` sets `max_payload_len` to 64, and the client drops an order past it (`OrderDropped`). A stable id of 128 to 16,383 takes 2 bytes, so a move holds at most 24 such units; one of 16,384 to 2,097,151 takes 3, so 16. Units, deliveries, actions and scripts allocate ids from one allocator, so the ids rise as a match goes on; the base play's last mob had id 1,694 at 270 s.
- **The drop happened in play.** In the client, a move of 25 units from id 143 was dropped twice, its 50 bytes of ids and 15 others one past the bound.
- **Zero Hour keeps each player's selection in its logic.** The client's `MSG_CREATE_SELECTED_GROUP` carries the ids of the units it selects, `GameLogic::onCreateSelectedGroup` makes them the player's selected group, `MSG_REMOVE_FROM_SELECTED_GROUP` takes units out of it, and a command applies to the group with no ids of its own (`Core/GameEngine/Source/GameLogic/System/GameLogicDispatch.cpp`). A message past a packet goes in chunks (`NetWrapperCommandMsg`). `InGameUI`'s `MaxSelectionSize` is -1, no limit, unless `InGameUI.ini` sets one (`InGameUI.cpp`).
- **Zero Hour's message fits about one packet.** Its retail game packet is 476 bytes, a UDP datagram of 512 less its headers, and a message is at most 1,024 bytes; TheSuperHackers' build sends 1,100 bytes of UDP payload, as mobile networks' MTUs run from 1,340 to 1,500 bytes, and a message as long (`Core/GameEngine/Include/GameNetwork/NetworkDefs.h`).
- **Campfire's datagram is 1,200 bytes,** QUIC's least MTU (`DEFAULT_MTU`), and its transport splits a longer message into fragments. A session's player holds at most `max_payload_len` × `max_per_tick` × (`max_lead` + 1) bytes on the server, 7,936 on the LAN terms.
- **Spring sends a selection, then commands.** `NETMSG_SELECT` carries a player's selected unit ids as `int16`s, and `NETMSG_COMMAND` an id, options and parameters, with no units ([NetMessageTypes.h](https://github.com/beyond-all-reason/spring/blob/master/rts/Net/Protocol/NetMessageTypes.h)).
- **StarCraft II records selection deltas apart from commands.** A replay holds a player's selection changes as their own events, a control group and a delta at a game loop, and its command events as orders to the selected units ([sc2-datasets SelectionDelta](https://sc2-datasets.readthedocs.io/en/latest/autoapi/sc2_datasets/replay_parser/game_events/events/selection_delta/index.html); [sc2reader game events](https://sc2reader.readthedocs.io/en/stable/events/game.html)).
