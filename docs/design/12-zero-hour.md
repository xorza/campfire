# Campfire — Zero Hour

Command & Conquer: Generals – Zero Hour, imported from the player's own copy and played on Campfire's sim, so close to the original that no player notices a difference. It is the first imported game ([Games](04-capabilities/games.md)): the `import` app, the parity method and the client's presentation systems it needs are the engine's, and each later import reuses them; the importer module, the rules package and the oracle are Zero Hour's.

## Decisions

- **D1. Zero Hour is the first import.** EA released the source of Generals and Zero Hour under GPL v3 in February 2025, so every rule has a written specification, and most of the game is INI data: an object is a list of modules from a fixed library, `Body`, `Behavior`, `Draw` and the rest, each with its fields. Zero Hour, not the base game, as the community plays it.
- **D2. The importer and the rules package are MIT/Apache-2.0, written from the released source.** Near parity means reading the original's formulas, the order of their operations and its pathfinder closely; the code is our own, and a release that ships it takes a legal check first, since code written that close to GPL code can be held a derivative of it. No file of the original, and no line copied from it, enters the repository.
- **D3. Generic modules are capabilities; what only Zero Hour does is Rhai; native code only behind a backend interface.** A module whose mechanism another game shares, a weapon, a body, production, a container, becomes a capability or an option of one. A module only Zero Hour has, a general's power, its veterancy rules, its crush damage, is Rhai in the rules package. The pathfinder and the locomotors, which Rhai cannot match in speed and a player feels in every move, are a pathfinding backend and a movement backend of navigation ([Backends](02-engine-core.md#backends)), so the core keeps no Zero Hour word. Movement is a backend interface of its own, how a unit follows its route each tick, whose default is the local steering every mode has now: Zero Hour's acceleration, braking, turn rates and locomotor types, infantry, wheels, treads, hover and air, stay inside its backend, quirks included, and no other game inherits them.
- **D4. One reproducible package.** The importer writes one package from an install, the game's data, its assets and every map, each map under `map/<name>/`, which a session names and alone reads ([Packages](05-protocol-spec.md#packages)), and the same install, game version and importer release give the same bytes on every OS, assets included: the session names it by fingerprint, as it names any package. So every encoder the importer runs, of models, textures and sounds, gives the same bytes on every OS, and an importer release that converts anything differently makes a new fingerprint. Nobody distributes an imported package: each player, each server and each verifier makes their own ([Packages](05-protocol-spec.md#packages)).
- **D5. The original is the oracle.** A fork of [GeneralsX](https://github.com/fbraz3/GeneralsX), the community's build of the released source for Linux x86-64 and macOS on Apple Silicon, gains a headless player of replay files that writes each logic frame's units and events. Campfire plays the same replays, imported as inputs, and a test compares the two. The measure of "no player notices" is set from the first measurements, not before them.
- **D6. The client's presentation is data.** The client gains generic presentation systems that read data: a model and an animation for each condition state of a unit, effect lists, particle systems, terrain, and the layout of the control bar. The importer maps Zero Hour's `Draw` modules, FX lists, particle systems, command sets and window files onto them; presentation scripts cover the rest ([Who runs what](03-game-scripting.md#who-runs-what)).
- **D7. Fixtures in the tests, the install on request.** No copy of the game enters the repository or CI. The tests read small files written by hand in the original's formats, a `.big` archive, a map and a W3D model, committed with the importer. A check outside the tests, as `lan-check` is, runs on request against the install `GENERALSZH_DATA` names, and fails when it names none, so a run with no copy never passes as one that checked; it imports, compares the fingerprint with the one the other OS gave, and plays the parity suite.
- **D8. The parity test replays the original's draws.** Zero Hour draws from one generator that its replay seeds; Campfire draws from its PRF, keyed by a seed the seed chain gives ([Determinism Core](09-determinism-core.md)), so the two never draw the same values, and a match drifts from its first draw. The oracle writes every value it draws, in order; in the parity test alone, the sim takes those values in place of its PRF, through a source in its internals, and a session always draws from the PRF. A draw the port makes at another moment, or in another order, than the original fails the test as any other difference does, so the port keeps the original's draws where they are.
- **D9. The skirmish AI is a server bot.** The AI runs outside the sim, in the server, as every bot does: it reads what its team's clients see, and sends orders that the server signs and logs ([Sessions](10-sessions.md#decisions), D4). The original's AI runs inside its logic and reads its state directly, so the port can play differently. The parity test checks the world, not the AI: the oracle writes the commands the original's AI players give, and the test gives them to Campfire's bot slots as bot inputs. The AI's own play is not part of the parity measure.
- **D10. Code bound to Zero Hour lives in `zero_hour` modules.** Its importer, its pathfinding and movement backends and its AI each sit in a module named `zero_hour` of the crate whose interface they serve, so no reader takes one for a general system ([Modules](02-engine-core.md#modules)).
- **D11. A unit of Zero Hour is a meter.** Every distance, speed and size keeps the original's number, so no scale rounds a value. So the widest body rises to 2,048 m, the power of two past Zero Hour's widest, a 1,196-unit object of the campaign, and its bridges of 1,117 ([Wide bodies](13-bodies-uses-shop-gravity.md#wide-bodies)).
- **D12. The rules package is of the kind `rules`, and the import writes it beside the imported mode.** A `rules` package holds scripts, and later data, that a mode depends on: a mode names one of its scripts as its own, `script = { package, path }`, and the load checks that script as the mode's own, with the mode's params. The import makes a directory of two packages: `zero-hour/`, the rules package as the importer ships it, byte for byte, and `game/`, the imported mode, whose manifest names it at `../zero-hour`, so the imported package's bytes, its fingerprint among them, name no path of the machine that imported it. A player starts the client on `game/`.
- **D13. The import converts a W3D material to the engine's one material, and writes down what it loses.** The engine lights every game alike, by Bevy's physically based standard material, which glTF and its extensions hold, and the material file, for what glTF cannot say ([The client](#the-client)); the importer alone knows W3D, and converts each material to it as near to the original as it can. A W3D mesh is lit per vertex by its ambient, diffuse and emissive colors, clamped, then textured, and no shader of the install turns its secondary gradient, its specular, on: so a material is rough, not metallic, of no specular, `KHR_materials_specular` at a factor of 0, which Bevy reads as no reflectance; a shader whose primary gradient is off, 3,247 of the install's, draws its texture alone, unlit, `KHR_materials_unlit`: white, opaque, of no emissive light and no vertex colors, as the game selects the texture's color and alpha alone (`ShaderClass::Apply`, `GRADIENT_DISABLE`); with texturing off, the game draws the vertices' light, as any lit shader. A mesh's second pass, 5,625 in the install, none a third, and a pass's second texture stage, its detail stage, 317, are layers: each one more primitive of the same triangles, with its own texture, coordinates, vertex colors and material, drawn over the one before at its depth, by a blend, its shader's or its detail function's, a scale a multiplying blend and an add an additive one, the blend and the depth bias in the material file where glTF cannot say them. A texture no archive holds draws as the game's `MissingTexture`, a solid `0x7FFF00FF`, as a player of the original sees it. What the conversion loses, which the engine's one material cannot hold: an ambient color apart from the diffuse one, which 3,094 of the install's 80,025 vertex materials have, and the lighting per vertex and its clamp, lit per pixel instead; a detail stage's alpha function, 144 shaders. No lighting rule of W3D enters the engine ([research](../research/zero-hour.md#models)).
- **D14. The objects the game gives the client alone are the client's.** The game spawns an optimized tree, a prop, and fluff, an object a build clears that is no fence, on the client alone, with no logic object, and in a single-player game by the machine's detail level and its tree setting, so two machines may simulate different objects (`GameLogic::startNewGame`). Campfire takes the multiplayer game's rule, the one that no machine's setting changes, in every session: those objects go to a client file of the map, and the sim, its log and its state hash never hold them; a shrub stays a unit, as multiplayer keeps trees on. They block no path in the original, so the sim needs none of them. The original's client removes them under a new structure and pushes trees aside or topples them as units pass (`W3DPropBuffer`, `W3DTreeBuffer`): presentation systems of the client, which read the units it holds. The parity oracle plays every replay by the same rule.

## The importer

A module of the `import` app, `zero_hour`, which reads an install through `store` and writes one package. What it reads, measured on an install and read from the source: [Zero Hour research](../research/zero-hour.md).

| Original | Package |
| --- | --- |
| `.big` archives | Read in place; nothing of them is kept |
| INI: objects, weapons, locomotors, upgrades, sciences, special powers, command sets | `data/`, each module to its capability's section or to the rules package's script with its fields as params |
| `.map`: heightmap, textures, placed objects, waypoints, triggers, scripts | `map/<name>/`: `map.toml`, its heights in `heights.bin`; the terrain's tiles and blends in `client/maps/<name>/terrain.bin`; the map's scripts as data the rules package runs. Each grid is postcard, a typed struct, exact and compact |
| W3D models, hierarchies and animations | glTF |
| Textures | KTX2, no supercompression, sRGB: a DDS's DXT blocks and mip levels as they are, as BC1, BC2 and BC3; a TGA as RGBA8, with mip levels the importer computes in integers |
| Audio | Ogg Vorbis |
| `.csf` strings | `locale/`, one Fluent file a language |

- **Which file.** The importer resolves each path as the original does: every archive under the install, in case-insensitive order of path, the first that holds a path keeping it, base Generals' `ZH_Generals/` last, and the duplicate `Data/INI/INIZH.big` skipped.
- **Maps.** Each map the game lists, `Maps\<folder>\<folder>.map`, becomes `map/<name>/` and `client/maps/<name>/`, read as the game reads it: unpacked by its tag, `EAR` by `RefPack` and `ZL1` to `ZL9` by zlib, and its chunks of the versions the shipped maps have, any other refused.
  - **Names.** A map's folder and an object's template become declared names: ASCII letters lowercase, digits and `_` kept, every other byte `_`, and `x` before a name that starts with no letter. Two folders, or two templates, that give one name fail the import.
  - **Axes.** The original's `x` east, `y` north and `z` up are the engine's `x`, `−z` and `y`, so the axes stay right-handed with `y` up. An angle keeps its sign, as a turn from `x` towards `y` is one from `x` towards `−z`, counter-clockwise seen from above; it is normalized as the game's `normalizeAngle` does, in `f32`, and turned into degrees rounded once. Every other `f32` becomes the `Num` of its exact value, rounded once only below ½.
  - **Heights.** `heights.bin` is a `HeightGrid` of `client-files`: a sample every 10 units, a step of 0.625, its rows the file's in reverse, so the first lies at the least `z`. The terrain's cells are in the same order. The import converts them to the generic terrain file, `client/maps/<name>/terrain.bin` ([Terrain](16-terrain.md)): each cell's tile its ground quad, its blend an overlay of its corners' alphas over the same split, and its third blend an overlay after it, as the game's heightmap renderer draws them, a cliff's tile stretched by its cliff UVs when `GameData.ini`'s `AdjustCliffTextures` says so, and the third blends kept when its `Use3WayTerrainBlends` is not 0, which the shipped install sets to 1. These rules are the importer's: the client reads only the generic file.
  - **Terrain textures.** Each texture class of a map names a terrain type of `Terrain.ini`, read as `TerrainTypeCollection` reads it, the default file first: the class's texture is that type's TGA under `Art\Terrain\`, as `readTexClass` opens it, written into the terrain file as the package's KTX2 path; a class no type names, or whose TGA the install lacks, has none. The import lays out the game's atlas as the terrain file's texture, its copies and its border wraps, which the client composes at load: each class a block of its tiles, 64 texels each, on a grid of 72-texel cells, the widest first, 2,048 texels wide, with a wrapped border of 4 texels and three levels, as `WorldHeightMap` lays it out; each quad's texture coordinates are its tile's place in it.
  - **Lighting.** A map's `GlobalLighting` gives, for each of the four times of day, three terrain lights and three object lights, each an ambient color, a diffuse color and the way its light goes; the import keeps the map's own time of day and the `NumberGlobalLights` of each that `GameData.ini` draws. The terrain is lit by the objects' lights, as every model is, and its own are lost, as [Terrain](16-terrain.md#losses-of-zero-hours-terrain) measures: on 91 of the 116 shipped maps they are the objects' own. The objects' go into `client/maps/<name>/lights.toml`, a generic file of an ambient color and directional lights, which the client gives Bevy's lights, each as strong as the camera's exposure and the diffuse term's π take, so a light of 1 gives a surface its full color. A game's light is added to sRGB codes, so the client takes each light color as an sRGB code, which linear light multiplies as the codes do.
  - **Game data.** `GameData.ini`, read as `GlobalData` reads it, gives the import whether cliffs stretch their tiles and whether third blends draw, and `client/camera.toml`, the generic camera file: the pitch, the yaw, the heights, and the scroll, turn and zoom speeds the game's view and its controls give, the scroll speeds as retail's at 800 pixels wide.
  - **Objects.** The game drops an object past its height range as it reads the map, and draws a road's or a bridge's ends as terrain: the import keeps neither. A waypoint becomes marker `w<id>`, tagged `waypoint`, its name in param `name`, at its ground point alone: the game reads neither its height nor its angle, so the import does not either. A template names its INI object of its case, as `ThingFactory::findTemplate` finds it, after the two renames of `handleNameChange`, `AmericaTankLeopard` to `AmericaTankCrusader` and `AmericaVehicleHumVee` to `AmericaVehicleHumvee`; an object whose template no INI object names is dropped, as the game drops it. An optimized tree (`KindOf` `OPTIMIZED_TREE`), a prop (`PROP`) and fluff (`CLEARED_BY_BUILD` with a `FenceWidth` of 0) ([D14](#decisions)) become client objects of `client/maps/<name>/objects.toml`, a generic file, a list of entries, each the name of its look in `client/units.toml`, its template's, its ground point, its height above the ground and its angle; a template that only client objects place is no unit type of `data/units.toml`. An `ObjectReskin` keeps its base's `KindOf` and `IsBridge`, which the game's reskin table cannot set and its release build skips, and may set its own `FenceWidth`. A bridge-like object, of `IsBridge` or of `KindOf` `WALK_ON_TOP_OF_WALL`, is a unit whatever its other kinds, placed before every other unit, in the map's order, as the game spawns bridge-like objects in a pass before the others: 12 of the install's templates, its landmark bridges, its train crash and its fortress walls. A client object whose look `client/units.toml` lacks, as its models are skipped, is dropped, as it draws nothing. Every other object becomes a placed unit of its template's type, on team `neutral`, with its `z` as its `height` above the ground. The map's bounds hold its heights and every point its sim places.
- **Textures.** Each `.dds` and `.tga` of the archives becomes `client/textures/<its path>.ktx2`, once, by the general texture module of the importer that any import uses. Every one is marked sRGB, as color textures are. A DDS keeps its DXT1, DXT3 or DXT5 blocks and its levels as they are; a TGA becomes 8-bit RGBA, rows from the top, with alpha in every texel of 32 bits whatever its header's count of alpha bits says, as Zero Hour's loader reads it, and its full chain of levels, each a box filter of the one above in linear light: each color decoded from sRGB by a table of 2⁻¹⁶ steps, which tests check exactly, the mean taken there, and the mean encoded back to the nearest code; alpha the plain mean, rounded half up; a side of `n` texels halving to `max(1, n / 2)`, each texel below an equal share of the side above, so an odd side's middle texel is shared by weight and none is dropped.
- **Objects' models.** The importer reads the object INI files as the game loads them, `Data\INI\Default\Object` then `Data\INI\Object`, each folder's files in the order of their paths. `=` is optional, and a line opens a block by its keyword: `Draw`, `Behavior`, `Body`, `ClientUpdate`, `ConditionState`, `TransitionState`, `AddModule` and `ReplaceModule` always; `DefaultConditionState`, `ArmorSet`, `WeaponSet`, `UnitSpecificSounds`, `UnitSpecificFX`, `Prerequisites`, `Turret`, `AltTurret`, the decals, `InheritableModule` and `OverrideableByLikeKind` only alone on their line, as `Turret = X` is a field. A file whose blocks do not close is refused. An `Object` of a name read before, and an `ObjectReskin` of a base not yet read, are refused: no known install holds either, of its 2,104 definitions, where the game's release build parses a second definition into the first template, and refuses a reskin of no base. An `ObjectReskin` is a copy of its base as the base stands when the reskin is read (`ThingTemplate::copyFrom`), so it keeps its base's draw modules unless it declares one, as the game drops every copied draw module at an object's first own one. Each draw module of the `W3DModelDraw` family (`W3DModelDraw` and its kin, `W3DTankDraw`, `W3DTruckDraw`, `W3DTankTruckDraw`, `W3DDependencyModelDraw`, `W3DOverlordAircraftDraw`, `W3DOverlordTankDraw`, `W3DOverlordTruckDraw`, `W3DPoliceCarDraw`, `W3DScienceModelDraw`, `W3DSupplyDraw`) gives the `Model` of its default state: its `DefaultConditionState`, which must be its first state, else its first `ConditionState`, which the game requires to be `NONE`; a default state that names no `Model` is refused, as the game refuses it; `W3DTreeDraw` and `W3DPropDraw` give their `ModelName`. A model of `NONE` is none.
  - **Default look.** The sub-objects the game hides in the default state, as `W3DModelDraw` sets them: those whose W3D mesh is hidden by its flag, then each weapon slot's muzzle flash, the first sub-object on each of the bones `<name>01` to `<name>99` while the slot finds any of its fire, recoil, flash or launch bones at that number, else on the bone of the bare name; then each `HideSubObject` and `ShowSubObject` in order, each also over the sub-objects on the strict child bones of its own bone. As the game reads them, a name keeps the place of its first change and takes its last, and `None` empties the list; a weapon bone `None` is none. Names compare ignoring case.
  - **Models.** Each model the objects name, once, at `client/models/<name>.glb`: the file `<name>.w3d`, or for `File.Mesh` the file `File.w3d`, looked for in `Data\<language>\Art\W3D\` then `Art\W3D\`, the install's one language folder; an HLOD on its hierarchy, from its own file or the hierarchy's, or a mesh alone. A mesh's name is `Container.Mesh`, or `Mesh` alone when its container's name is empty. `NULL`, the render object the game always has, and a collision box draw nothing, as no code of the game sets `Set_Box_Display_Mask`: a draw module of either gives no model, and an HLOD keeps a box's sub-object for the default look and gives it no node. An HLOD's sub-object that names no render object is dropped, as `HLodClass` drops it. A particle emitter is not converted, and the import reports it with the models no file holds. The importer refuses a mesh with no material pass, of which none ships, a drawn mesh of no triangle, which glTF cannot hold, and a position, normal, opacity or pivot that is not finite. The glTF keeps W3D's pivots as nodes, each sub-object a node on its pivot's node named by its mesh's name; W3D's `z` up becomes glTF's `y` up, `(x, y, z)` as `(x, z, −y)`, a quaternion's axis the same way, which is a rotation, so triangles keep their counter-clockwise front. A skin's vertices are placed by each one's bone into its bind pose. A mesh's positions, normals, its first pass's first stage's coordinates with `V` read as `1 − V`, as the game reads it, or `0, 0` at every vertex when the stage has none, a coordinate that is not finite 0, and its vertex colors; of each list, the first chunk that holds it, as the game reads a later one into a material the default look does not show. A normal of zero, which glTF forbids, becomes the sum of its triangles' normals by area, made unit, or up if they sum to zero or none uses its vertex; the game lights such a vertex by ambient and emissive light alone, which no normal gives. Its triangles go in one primitive for each texture, shader and vertex material, a triangle's vertex material that of its first vertex, and a triangle of texture id `0xFFFFFFFF` untextured. A second material pass draws the same triangles again, after the first: one more primitive for each of its texture, shader and vertex material, of its own stage's coordinates and vertex colors, as the first pass's are, writing depth only where its shader does ([D13](#decisions)). A pass's second texture stage is its detail stage, as the game counts a pass's stages, and a third, which the game cannot hold, is refused: a layer over its pass, one more primitive for each of its texture and shader whose detail color function mixes it, of the stage's own coordinates or `0, 0`, no vertex colors, and a material white, unlit, writing no depth, by a multiplying blend for scale and an additive one for add, as the game mixes the detail's color into the lit first stage's; a shader whose function keeps the first stage alone, or that draws no texture, draws no detail, and any other function, which no shipped shader uses, is refused. Each layer's depth bias is one more than that of what it covers, in the order the game draws them: the first pass 0, its detail stage, the second pass, and its own; every material with a depth bias has a material file. Vertex colors are glTF's `COLOR_0`, which multiplies the base color: the game multiplies them by the diffuse color and opacity when the vertex materials give diffuse light and no emissive light, which every shipped mesh with vertex colors does; an unlit material takes none, as the game draws its texture alone; any other mesh with vertex colors, of a triangle a lit shader draws, is refused. A node's name is unique in its model, as a default look hides nodes by name. A material is the vertex material's diffuse color and opacity, its emissive color, the texture, its clamping, and the mesh's two-sided flag; a texture is its name with the last three letters made `dds` if the archives hold that, else the name itself when it is a `.tga`, as the game's TGA reader reads only those, each looked for in `Data\<language>\Art\Textures\` then `Art\Textures\`, and named by its KTX2 file's path from the model; a texture no archive holds draws as `MissingTexture`, its triangles' material color multiplied by the game's `0x7FFF00FF` in place of a texture, its alpha as the mesh's shader takes it, and the import reports it. An opaque shader, an alpha test, at 96 of 255 as the game sets it, and a blend by source alpha are glTF's own modes; any other shader, an additive one or a blend with an alpha test, writes a material file; a material is rough and of no specular, unlit for a shader whose primary gradient is off, and a second pass or a detail stage a layer ([D13](#decisions)). Each material is named `<model>_<index>`.
  - **Units.** `client/units.toml` lists every object with a model, each model at its template's `Scale`, its asset scale, 1 when the INI gives none, as every drawable of the game takes it (`Drawable`, `W3DTerrainVisual::addProp`); a reskin takes its base's, as its table cannot set its own, and a `Scale` that is not positive is refused.
- **Versions.** The importer knows each game version it supports, by the hashes of the files it reads, and refuses any other with the version it found.
- **Times and numbers.** Zero Hour runs 30 logic frames a second, and its mode allows 30 Hz alone. The original states times in milliseconds and turns each into frames by its own rule; the importer applies that rule and writes the milliseconds that Campfire's rule, rounded up, turns into the same count, so no time moves by a frame. Each decimal becomes a `Num`, rounded once at import.
- **Replays.** A `.rep` file is the commands of each player by frame: the importer turns one into Campfire inputs, for the parity tests.

## The rules package

`source/packages/zero-hour/`, an ordinary package that holds no file of the game and ships with the importer. The imported package is the mode: its manifest, data, maps and assets; it depends on the rules package, and its mode data names the rules package's mode script, `script = { package, path }` ([Data files](08-script-api.md#data-files)).

- The table from each module type to the capability or the script that runs it, which the importer reads.
- The Rhai scripts of the modules only Zero Hour has.
- The modes: the skirmish's setup and its end.
- The presentation scripts, and the control bar's rules, without its images.

The order of the work is the module audit's: every module type of Zero Hour's INI, with the count of objects that use it, and its place, a capability, a script or a backend.

## Parity

- **The oracle** plays a replay headless and writes, each frame, every object's id, type, owner, position, health and state, each event, a shot, a hit, a death, a build, a train, a power, each value it draws, and the commands of its AI players.
- **The test** plays the same replay in Campfire and compares frame by frame: the first difference past the measure fails the test, with the frame, the object and the field.
- **The suite** is a set of community replays that covers the module types the import runs, each in its own test, as a replay is a scripted match whose script a player wrote.
- **Randomness.** The test gives the sim the oracle's draws ([D8](#decisions)), so a random outcome is the original's.
- **Client objects.** The oracle spawns a map's objects by the multiplayer game's rule in every replay, as Campfire does ([D14](#decisions)).

## The client

An imported package's models and textures reach Bevy through a package asset source, `package://<place>/<path>`, a package's place among the mode's, the mode's 0, then its path in it: its reader reads through `package` and `store` and checks each file against the package's index, on Bevy's IO pool, and Bevy's own glTF and KTX2 loaders parse the bytes, on demand, a model's textures by their paths in the same source. A unit is drawn at its place, its position's height above the drawn ground beneath it, each cell split as its terrain draws it ([Units that drive](17-units-that-drive.md#decisions), D8); each of its type's models turned the way it faces. The pointer's ground point is where the cursor's ray first meets that ground.

A unit type's presentation is data of its package's client, `client/units.toml`: `[units.<id>]`, the type's name in the package that declares it, which `capabilities`' `TypeOriginBook` gives by unit type, or an avatar's package's name, with `models`, a list, each a `.glb` of the package, its scale, 1 when it gives none, and the names of the nodes its default look hides, all drawn at the unit's place; as the presentation systems grow, a model and an animation for each condition state. A type with none is drawn as the engine's own shapes are. The sim reads no part of it.

A glTF material says less than a game's shader can: no additive blend, no blend with an alpha test, no depth bias. So a material file, `client/materials/<name>.toml`, overrides the glTF material of that name whole, so it holds all a glTF material of the import holds: its base color and texture, its emissive color, its metallic and roughness factors, its specular factor, as `KHR_materials_specular`'s, whether it is unlit, as `KHR_materials_unlit`, its blend, opaque, an alpha test with its cutoff, a blend by alpha with or without a test, additive, multiplying or screen, whether it writes depth, its depth bias, by which a layer draws over the primitive before it at the same depth, and whether it draws both faces; it is no lighting rule, as every material lights alike. A material with no file is the glTF's own; one with a file is drawn by an extension of Bevy's standard material, whose pipeline takes the file's blend factors and depth write and whose shader takes its alpha test, and draws it unlit where the file says, as Bevy's own shader does. Both formats are general, of the package API, and Zero Hour's import is their first writer. A layer is a primitive of the same vertices, so its fragments lie at the depth of the primitive under it, which Bevy's depth test of greater or equal passes; it draws after it, a blend in the transparent phase, and its depth bias sorts it after the one under it where both blend.

A map's client objects, `client/maps/<name>/objects.toml`, are drawn at their places by their looks, still, standing on the map's heightmap as units do, and are no part of the sim ([D14](#decisions)); the presentation systems that remove them under a new structure and topple trees as units pass read the units the client holds.

The presentation systems of [D6](#decisions), generic, which every imported game uses: a unit's model and animation follow its condition state, as Zero Hour's `W3DModelDraw` does; an event plays its effect list; terrain draws from its heightmap and texture blends; the control bar lays out the commands of the selected units. Floats stay in the client, as everywhere ([Bevy](02-engine-core.md#bevy)).

## Open questions

- **Sound.** Which WAV encodings the game holds, and an encoder of Ogg Vorbis that gives the same bytes on every OS. Models and textures need none: the importer writes the GLB and KTX2 containers itself, glTF's JSON through `codec`, and copies or computes their contents in integers.
- **The measure.** Its numbers, from the first measurements of the oracle against Campfire.
- **The AI's play.** How the port's skirmish AI is compared with the original's, as the parity test leaves it out ([D9](#decisions)).
- **The oracle's own determinism.** Whether GeneralsX plays a retail replay to the same end on Linux and on macOS, which the first slice checks.
