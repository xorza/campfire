# Campfire — Determinism Core

Numbers, vectors, randomness, stable ids and the state hash: the base every result depends on.

## Decisions

- **D1. Own `Num(i64)`, 40.24, `*` and `/` rounded to nearest, ties to even.** No downward drift, one rounding rule everywhere. 40.24 over 32.32: 256× more range (±5.5 × 10¹¹), so script products overflow far later; the resolution, 6 × 10⁻⁸, stays far below anything a player sees.
- **D2. `round()` to an integer is half away from zero** (`2.5 → 3`, `−2.5 → −3`). What script authors expect.
- **D3. Coordinates stay within ±2²⁰ m.** Exact squared distances fit a `u128` with room to spare: `3 · (2⁴⁵)² < 2⁹²`.
- **D4. `proptest` for tests, `criterion` behind `bench`,** each added with the first code that uses it. Differential tests find rounding cases no table lists; the worst tick must be measured.
- **D5. One BLAKE3 hash per component type, then a hash over those.** The first divergence names its component type at once.
- **D6. No `fixed` or `fixed_analytics`; own parser, constants and trig.** `fixed` rounds `*` toward −∞ and its constants down; `fixed_analytics` reaches 48 ulp in `atan2`. Own series at high internal precision stay within 0.501 ulp over the tests' sweeps.
- **D7. `From` only where every value converts exactly; `TryFrom` where one can fail.** As the Rust API guidelines' C-CONV says: `Num` from each integer type its range holds whole, `i8` to `i32` and `u8` to `u32`; `Vec3` from a triple, a tuple or an array, of such values or of `Num`; `Position` from a triple of `i16`, as every `i16` lies within ±2²⁰, so a literal past the bound does not compile. `i64` and `u64` to `Num`, and `Vec3` to `Position`, are `TryFrom`. No conversion panics: `Num::int` stays the `const` constructor of a literal. An identity, `Team`, `PlayerSlot`, `Tick`, `Ticks`, `StableId`, has no `From` of its integer, which has no meaning of its own; a pair has none to a `Position`, as its axes are not known; and no float converts.
- **D8. One step: an `i128`, rounded once.** Every operation of `math` computes its result from its inputs in one `i128` and rounds it once, to nearest, ties to even, or by the `Rounding` a rule names; no type of `math` is wider than 128 bits. Where an exact result would pass 128 bits, it rounds an input first, by an amount its doc comment states: the exactness given up is at most two bits of a `Num`, 2⁻²³ m, which no player sees, and every result stays the same bits on every machine. Engines that run a deterministic sim on fixed point keep one 128-bit step as their widest, as Photon Quantum's Q48.16 ([Quantum](https://doc.photonengine.com/quantum/v2/manual/quantum-ecs/fixed-point)) and `mas-bandwidth/fixed` ([fixed](https://github.com/mas-bandwidth/fixed)) do; floats made deterministic, as Box2D v3's ([Box2D](https://box2d.org/posts/2024/08/determinism/)), are not taken, as the client runs the sim in a process whose other code may set a thread's flush-to-zero, and a NaN's bits would reach the state hash.
- **D9. Exact where it fits; a distance to a line to the nearest bit.** A test between two points compares squares, exactly, below 2⁹² in three axes. A distance to a line, a segment or a box's edge, and a place along a path, its distance from the start, come from the line's `Direction`, each to the nearest bit, within 0.51 of a bit, or 1.4 from a line in three axes; a point's distance against a reach orders its nearest root with no root. A box's entry onto a path is `meets_path`'s exact answer, its place the latest of its slabs' entries, `(bound − value) · length ÷ along`, below 2¹²⁷.
- **D10. A push rounds away from what it leaves.** The push of two circles is the offset's direction `reach` long, each axis rounded away from zero past the direction's own rounding, so they end touching or apart, under a bit past on each axis; a push out of a box goes `PUSH_SLACK`, a bit, past touching, the most a box's measure of a distance lies from the true one, rounded up, so the next measure sees the body apart: the one tolerance of collision, defined beside the push.
- **D11. A compound value is a chain of rounded steps.** A stat is `add`, then times `1 + pct`, then times `1 − cut`, each a `Num` product rounded to nearest and stopped at the range of a number, within a bit of the product rounded once; a scaled param sums each ratio's product, rounded to nearest, unsaturated in an `i128`, and stops only the sum, so products past the range still cancel.
- **D12. A test's exact reference may be wider.** A differential test checks each rounded step against an exact reference; one that passes 128 bits, a schoolbook product of digits, lives in the test that needs it, never in the crate's API.

## Design

- **`Num`:** 40.24 fixed-point in an `i64`. Checked arithmetic; `*` and `/` round once, to nearest, ties to even. A rule that rounds another way, as a share of a value rounded down or an attack's period in ticks rounded up, names its `Rounding`, `NearestEven`, `Floor` or `Ceiling`, as Java's `BigDecimal.divide` takes a `RoundingMode`, in `checked_div_rounded`, `checked_mul_div` and `checked_mul_ratio`, each from the exact product, rounded once; an `i128` quotient and shift round by the same `Rounding`, so no caller rounds on raw bits. An overflow in engine code panics, and in a script it is a script error. Data strings parse exactly, with an error on bad input. No conversion from or to floats.
- **Roots and trig:** `sqrt` and vector lengths are exact to the nearest value, `FloorRoot` gives the exact floor root of any `u128`, and of four `u64`s at once in lanes, and `RoundedRoot` a `u128`'s nearest and ceiling roots from it, and how its nearest root orders against a value, with no root ([Libraries](02-engine-core.md#libraries)); a float gives only the first estimate, which integer steps correct, so the result never depends on it. `sin_cos` and `atan2` come from tabled series computed at compile time, in integer steps, so they give the same bits on every machine. The design claims only the bound the tests prove, within 0.501 ulp of `f64` over sweeps of angles and points: no search of the values near a rounding midpoint proves them correctly rounded.
- **`Vec3`:** checked operations; `dot` and rotations round once; `within(other, radius)` compares exact squared distances, with no root.
- **`Direction`:** the direction of a vector of two or three integer axes, a unit vector with 62 bits of fraction, and its length, each rounded to nearest; what it measures of an offset, how far along it and how far from its line, rounds once more, to the nearest unit: within 0.51 of a unit, or 1.4 from its line in three axes (D9). A distance to a line, a segment or a box's edge, and a place along a path, are measured so; a test between two points compares squares, and a point's distance against a reach orders its nearest root with no root, by `NearestRoot::nearest_root_cmp`.
- **`Rng`:** one BLAKE3-keyed sequence per (stream, entity, tick), keyed by the segment seed, so no draw depends on another's order and systems can draw in parallel. `below`, `chance` and `chance_ratio` are exact; `chance` always takes one word. `math` opens a sequence from its seed, stream, entity and tick, and keeps no state; the sim's `SimRng` keeps the running tick and how many ticks it started, opens that tick's sequences, and hands out an `RngOpener` for a script call, which holds no world. Debug builds panic when a tick opens one sequence twice. A stream is an `RngStream`, a constant its owner declares, such as combat's `combat.roll`: a name of 1 to 64 lowercase letters, digits, `_` and `.`, checked when it is built. The streams belong to several crates, so each owner names its own, not a closed enum in `math`.
- **Stable ids:** handed out in order and never reused; the index of ids to entities is the order every hash walks. An entity a match holds once, the match's and each player's, takes a named id from 2⁶³ up, past every id the allocator hands out, so its spawn moves no unit's id or anything keyed by it; a restore checks the allocator against the allocated ids alone.
- **State:** each state type has a fixed name, and the registry hashes, snapshots and restores all of them in name order, then by stable id. A snapshot holds exactly the bytes the hash reads, so they cannot disagree. A restore reads untrusted bytes and returns an error for every flaw, never a panic. It restores into a match whose books the packages loaded. Every snapshot holds each state resource, and a restore refuses one that records a resource as absent, so no system meets a resource missing. Once every type is decoded, each value is checked on the kind of entity its type names, `SimComponent::Host`: a body unit (`BodyUnit`), a delivery, a projectile or an area (`DeliveryEntity`), either of the two as a unit (`UnitEntity`), the match's entity or a player's. Each entity is of one kind, which its marker names: a second marker panics outside a restore, and a restore refuses it, as each kind's check holds its entity to one kind. Each holder must hold the parts that later systems read: a unit its position, its team and each state class its type declares; each entity the parts the modules declare for its kind, a player its resources and modifiers, the match's entity its relations and the mode's state, a unit of a type the mode spawns its parts from its type's books; a respawn its `Dead` and spawn point. Then each value is checked against the books and the other types: a unit type, team, player, path, action, rank, modifier, stat place, param, track or damage kind must be one the match has, a mode's or a modifier's state must have its declared fields' types, and a unit with a route must walk as one of the mode's kinds of walker. The check and the host are required items of the state traits, so the compiler proves that every state type has both.

## Tests

- Every operation has hand-computed cases, including ties, limits and sign changes, and `proptest` differential tests against exact references.
- Trig and `sqrt` stay within 0.501 ulp of `f64` over sweeps; the RNG passes the official BLAKE3 vectors; the state hash is the same whatever order a world was built in, and a snapshot restores to the same hash.
- The **golden test** hashes fixed workloads, one digest per section (`num`, `trig`, `vec3`, `rng`, `state`), and CI requires the same digests on every platform. They change only when a release changes results on purpose.
