# Bug reports

A slice's proposal. At its end, a player who sees a bug presses F12 in the client and gets a folder with the session's log up to that tick, a screenshot and the camera; an agent replays the log to that tick and reads the units there, and opens the report in the client to see the same frame. Its plan is `PLAN.md`'s Bug reports; when the slice ends, each lasting decision moves into the document of the system it governs, and this file is deleted. Its facts are [Bug reports](../research/bug-reports.md).

## Decisions

- **A report is a folder of plain files.** The key map's `report` chord, F12 by default, writes `<data>/reports/<session>-<tick>/`, a later report of the same tick, as a paused match draws, `-<take>` after it: `report.toml`, of the engine's release, the mode, the map, the session, the tick drawn, the player slot, the selected units, the camera and the window's size; `screenshot.png`; and in a local match, `session.campfire-log`. The player and an agent read each with the tools they have, as Unreal's `BugIt` leaves a screenshot and a line of the camera. Refused: one archive, which needs an unpacker before its screenshot shows; a report sent anywhere, which takes nothing off the machine unless the player gives it.
- **The camera is the rig's state.** The report holds the rig's pivot, yaw, pitch and height, which put the camera back exactly, as `BugItGo` takes a location and a rotation, and beside them the camera's place and its forward in the world, for a reader. Refused: the view's matrix alone, which no rig state gives back exactly.
- **The log is the local server's, published at the report's tick.** The client's local server settles its journal and publishes the log so far, its seed revealed, as its session's end publishes it, so the log replays to the report's tick; a load before the log reaches that tick drops the report's log, as the log then reaches it in another history. A remote session's report names its session and its tick, which the server's log holds once the session ends. Refused: a save, which holds the state at the tick but not the history that led to the bug; the client's own copy of the inputs, which lacks the other players' and the bots'.
- **The screenshot is the frame the window shows.** Bevy's `Screenshot` of the primary window captures it, `codec` encodes it as a PNG, and `store` writes it. The frame encodes and writes on the main thread as it arrives, one hitch per report, as Bevy's own `save_to_disk` writes it. Refused: `save_to_disk`, which writes past `store`; an uncompressed PNG, of 66 MB at 7680 × 2160; a worker of the thread list for a key a player presses once per bug.
- **A report replays to its tick.** `cargo drive run report <dir>` replays the report's log to its tick and writes a table of its units there, of the fields and the units the check's probes take, and `--probe <period_ms>:<units>` a table of each period before it, as Factorio reads a desync report's states. Refused: the verifier, which ships to players and checks a log whole.
- **The client opens a report, planned.** `campfire-client --local --data <dir> --report <report>` replays the report's log on the local server to its tick, pauses there and puts the camera at the report's, so the same frame shows, and a press of the `report` chord there writes the next report beside it.

## Checks

- The client's tests write a report of a fixed scene: its `report.toml`, a camera that reads back to the same rig, and a PNG that decodes to the captured frame.
- A test of the local server publishes its log at a tick and replays it there to the hash the session held at that tick.
- `cargo drive run report` on a report of a scripted match tables the units the match held at the report's tick.
- In the client, a player presses F12 in a Zero Hour skirmish, and an agent opens the report and sees the same frame.
