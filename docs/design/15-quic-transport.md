# Campfire — QUIC transport

The server and the client link over QUIC alone, through `quic`, an IO layer on `quinn-proto` under Lightyear's `Link`, in a crate of its own that `net` uses. QUIC alone, not WebTransport: WebTransport is HTTP/3 over QUIC, and its one gain is that a browser reaches it, which Campfire dropped ([Code](../../AGENTS.md#code)). The facts behind each decision are in [the research](../research/quic.md).

## Decisions

### The stack

- **D1. QUIC on `quinn-proto`, in its own crate.** `quinn-proto` is QUIC with no IO, the core of `quinn`, over `rustls` and `ring`, with RFC 9221's datagrams and TLS's exporter. Not `quinn`, whose API needs an async runtime; not `noq`, whose multipath and NAT traversal no slice needs yet; not `quiche`, a C library with no exporter; not `s2n-quic` or `neqo`, with their own IO or NSS; not Lightyear's UDP, with no encryption or congestion control, nor its netcode, whose tokens need a second protocol. `campfire-quic` depends of Campfire's crates on `common`, `store` and `log` alone, so it holds no game type, and `net` keeps what is Campfire's: the server's key and the meaning of a close.
- **D2. The socket is `quinn-udp`'s.** It reads and writes in batches, turns on ECN, and gives each datagram's destination, so a server bound to `0.0.0.0` replies from the address the client reached; it keeps its OS files behind one API ([Platform](02-engine-core.md#platform)). The server binds before its app runs, so a port in use ends the start with an error naming the address. A client binds port 0 of its server's address family.
- **D3. A thread for each endpoint, and the frame does no IO.** The thread waits through `polling` for the socket, the earliest deadline, or a wake; it reads one batch with no lock, takes the mutex it shares with the app for that batch, and writes after it lets go. So acknowledgments and keep-alives go on through a stalled frame, and a frame waits at most one batch for the mutex. The frame moves datagrams between the connections and Lightyear's links, in `BufferToLink` and `LinkSystems::Send`, and wakes the thread once. The queues between the two are `quinn-proto`'s own, bounded; no channel and no runtime. An endpoint's drop joins its thread.
- **D4. Datagrams, not streams.** One Lightyear packet is one DATAGRAM frame: Lightyear keeps reliability, order and fragments, QUIC keeps encryption, congestion control and the path MTU. The transport parameters let the peer open no stream, as the IO would read none. A full send queue drops its oldest datagram, as the newest state matters most.
- **D5. A link's minimum MTU is QUIC's datagram.** `LINK_MIN_MTU` is `1200 − (1 + 8 + 4 + 16) − 9 = 1,162`: QUIC's minimum path, a short header with ids of 8 bytes, a packet number of at most 4, an AEAD tag, and the DATAGRAM frame's type and length. Every link takes it from its spawn, in-process ones too, as Lightyear fixes a link's fragment size when its transport is added, and both ends must agree. The current MTU follows the connection's `max_size`. A connection whose datagrams cannot carry `LINK_MIN_MTU` on the minimum path is closed: only a peer with longer ids or a smaller `max_datagram_frame_size` makes it so.

### The server's key

- **D6. A raw key, derived from the server's key.** The server presents an Ed25519 key with no certificate ([RFC 7250](https://www.rfc-editor.org/rfc/rfc7250)), as no client reads a certificate's names or dates. Its seed is HKDF-SHA256 of the server's own key, label `campfire/tls/v1`: one secret file, so the pin cannot be lost while the identity stays, and no expiry. The listing names it as `TlsKey`; the client's verifier takes that key alone, and refuses any other with TLS's `access_denied`.
- **D7. TLS 1.3, ALPN `campfire`, no client key, no resumption.** A player proves its key by the connect answer, not by TLS. No session ticket, so every handshake presents the key and the verifier checks it, and no early data.

### Connections

- **D8. Retry, migration, and resets after a restart.** The server answers each new address with a stateless Retry ([RFC 9000](https://www.rfc-editor.org/rfc/rfc9000) §8.1), and sends no `NEW_TOKEN`, so a spoofed address costs no state. Keep-alive 1 s, idle timeout 5 s. A client whose NAT moves it keeps its link. The stateless reset key is HKDF of the server's key, label `campfire/quic-reset/v1`, so a server started again resets its old connections at their next packet (§10.3), and clients rejoin at once.
- **D9. The endpoint owns the connections; a link's entity is its peer.** The endpoint holds its connections in a table by handle. A server takes connections from its `LinkStart` to its `Unlink`, and spawns a link's entity only once a handshake completes, whole, its `RemoteId` the entity itself: an address is no peer, as QUIC holds two connections from one address and moves one to another, and Lightyear's patched raw server keeps that id. A link entity holds its endpoint weakly; its removal, by any path, closes its connection.
- **D10. A link's end is a type.** A link holds `LinkEnd` from its unlink to its next link: how the IO lost it, or `Closed` with the code its own end closed it with. `CloseLink` closes with an `AppCode`, which the peer reads back; codes below 16 are `quic`'s, `net`'s `CloseCode` names the rest, and `LinkLost` logs a `LinkLossCause`. So a peer that ends a link ends the other at once, and says why; an app's exit closes every connection with `STOPPED`.

### The connect answer

- **D11. The answer binds to the TLS session.** Both ends read RFC 9266's `tls-exporter` binding ([RFC 9266](https://www.rfc-editor.org/rfc/rfc9266)), which the link holds as `LinkBinding`, and the answer signs `"campfire/connect/v2" ‖ challenge ‖ binding`. A party that holds the server's TLS key and relays an answer holds two sessions, whose bindings differ, so the relay fails. In-process links take one fixed binding; the challenge keeps an answer fresh where there is no TLS.
