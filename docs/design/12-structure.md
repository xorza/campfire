# Campfire — Structure and names

How the workspace lays out its files, names its types, and shares what more than one crate or binary needs: one rule for each kind of value, one place for each error, one name for each meaning, and one copy of each piece of wiring. The proposal changes no behaviour but one flag name, the messages of errors (U5), and the binaries' usage errors, which gain `--help` (U12), and every step but the first ones of the shared parts is a pure refactor. It comes from an audit of the workspace after [Storage and workers](11-storage.md).

## Today

The workspace keeps most of its own rules: no `foo.rs` sits beside a `foo/`, no production code uses `super::`, `pub(in …)`, a tuple return or a re-export outside `lib.rs`, and every crate of the deterministic core denies the same lints. What the audit found:

- **Values of 32 bytes.** Five types wrap `Bytes32`, with the same body and different derives: `StateHash` and `Fingerprint` in `common`, `SessionId`, `CertificateHash` and `SnapshotFingerprint` in `protocol`. `CertificateHash` has no `Hash`, only `Fingerprint` has `Ord`, and `Fingerprint` and `SnapshotFingerprint` have no `FromStr`. Five more wrap a bare `[u8; 32]`: `InputHash`, `SeedCommitment`, `ConnectChallenge`, `ServerSeed` and `SegmentSeed`. A delegation's id is a bare `[u8; 32]` in `Delegation::id`, `Receipt::delegation` and `DurableHead::delegation`, as are a delegation's `seed_contribution` and `sim`'s `TypeHash::hash`.
- **Exit codes.** The server's storage failure is a named `74`; a bad command line is a bare `2` in the client, the server, the verifier and the LAN check, six places. The client and the server each turn an `AppExit` into an `ExitCode`.
- **The binaries.** The client and the server each have `fill` and `unix_now`, a `BotFile`, a parse of `<slot>=<orders file>`, and a read of an order script from its file. The flag is `--server-bot` on the client and `--bot` on the server. Each `Args::parse` gives its error as a `String`. The loop that makes a random key is in the client and in `net`'s `KeyFile::read_or_create`.
- **App wiring.** Three places build a server's app, the server, `LocalServer` and the test harness, each with `ServerPlugins`, `NetProtocol`, `SimServer` and the same `ReplicationSender` observer; three build a client's, the client, the harness and the local server's test, each with `ClientPlugins`, `NetProtocol`, `SimClient`, a `PredictionManager` and the same client entity. A headless frame of 2 ms is written in three places.
- **Errors.** 65 error types write `Display` and `Error` by hand, 1,345 lines. They sit in two kinds of place: `net`'s `error.rs` holds seven errors, most of one module each, while three of its modules hold their own; `runner`, `script`, `server` and `verifier` keep every error at the crate root; `package`'s `error.rs` is 932 lines with 14 types.
- **Test helpers.** A key from one byte is written more than 15 times. Temporary directories are made three ways: `tempfile::TempDir`, `store`'s `ScratchDir` and `net`'s `Scratch`, and by hand from `env::temp_dir()` and the process id in five unit tests, which leave their directory when they panic. `runner`'s two scripted matches each define `Aim`, `TICK_HZ`, `order` and `cast`.
- **`net`.** 47 modules at the top: the client's are in `sim_client/`, the server's 17 lie flat beside those both sides share. "Local" names the singleplayer server (`LocalServer`, `LocalSession`, `LocalPace`, `LocalRelink`) and the in-process test harness (`LocalMatch`). "Data" names a package's file data (`ActionData`, `MapData` and 20 more) and a data directory (`ServerData`, `ClientData`).
- **Names.** Five public names mean two things in two crates: `Speed` (`net`, `capabilities`), `LoadError` (`package`, `protocol`), `SlowSync` (`store`, `net`), `Level` (`log`, `capabilities`) and `Outcome` (`protocol`, the LAN check). Three names mean two things in one crate: `Carried` and `Reach` in `capabilities`, `Shared` in `store`. In `capabilities`, five effect types take their module's name (`AbilitiesEffect`, `CombatEffect`) and five their subject's (`AreaEffect`, `RevealEffect`); two view columns take their subject's (`TracksColumn`, `SightColumn`); the units' API is `position_api.rs`; and `TagEffect` is not an `Effect`.
- **Benches.** Six crates have eight bench targets: `math` has one for each of `num`, `rng` and `vec3`, so its benches are three binaries and three commands. `protocol`'s two cases have no group, so their ids name no subject. Each bench function makes its fixture before its first case, so a filter that skips every case still pays for it: the runner loads the reference 3v3's packages, and `net` starts two matches, to run none of them, and `--list` waits for both.
- **Files.** `session_log/mod.rs` is 1,831 lines and holds the public `SessionHeader`, `Applied` and `DurableHead`; `sim_server.rs` holds the public `TickHashes` and `PlayerLink`. Twenty-three files keep inline tests past 40% or 150 lines of the file. Eleven free `pub(crate)` functions remain. `sim`'s `Drawn` and `Variant` have no `Debug`. `capabilities`' `lib.rs` lists its layers without `items` and `books`, which the layer test holds. `runner` keeps 11 harness modules among its production ones, and its event and `verifier`'s sit at the crate root, while `net` keeps its in `events/`. The keys of a package's content are listed twice, as `PackageContent`'s fields and as `package`'s `KEYS`.

## Decisions

- **U1. One rule for a value of 32 bytes.** A public value wraps `Bytes32`; a secret, `ServerSeed` and `SegmentSeed`, wraps `[u8; 32]` and has no `Display`. Each is a type of its own, written by hand, in its own file with its own doc, and each has the same derives: `Debug`, `Clone`, `Copy`, `PartialEq`, `Eq`, `PartialOrd`, `Ord`, `Hash`, `Serialize` and `Deserialize`, serde transparent; `new` and `as_bytes`; a derived `Display` as 64 lowercase hex for a public one (U11); and `FromStr` only where text from outside names it, today `StateHash`, `SessionId`, `CertificateHash` and, in a delegation's tag, `SeedContribution`. A generic `Hex32<Kind>` would let no crate but `common` give one its own methods, as `SnapshotFingerprint::of`, and a macro is not needed where plain code works. A delegation's id becomes `DelegationId`, its seed contribution `SeedContribution`, both in `protocol`, and `TypeHash::hash` a `Bytes32`.
- **U2. One enum of exit codes.** `ExitStatus` in `common`: `Success` 0, `Failure` 1, `Usage` 2 and `Storage` 74, each with its `code`. The values do not change: `2` is what `clap` and the shells give a bad command line, and `74` is sysexits' `EX_IOERR` ([D9](10-sessions.md#decisions)). It enters `common` as the verifier and the client, which do not depend on each other, both name it. `ServerExit::STORAGE_FAILED` goes; `net` turns an `AppExit` into an `ExitCode` once, for the client and the server.
- **U3. One copy of what the binaries share.** `net`, which the client and the server both depend on and whose setups take a clock and a source of entropy, gives the OS's: `fill`, from `getrandom`, and `unix_now`. `protocol`, which owns `secp256k1`, makes a random key from a source of entropy, for the client and `KeyFile`. `net` reads a bot of a server's: `SlotBotFile`, which parses `<slot>=<orders file>` and reads its order script into a `SlotBot`, each failure a variant of its error; and `OrderScript::read` for a script in a file. Both binaries name the flag `--server-bot`, as the client's `--bot` already names the client's own script; the server's `--bot` of [Server bots](10-sessions.md#server-bots) becomes `--server-bot`, and both take their flags in any order. Each binary reads its command line with `clap` (U12).
- **U4. One copy of each app's wiring.** `SimServer`, given the tick's length, adds `ServerPlugins`, `NetProtocol` and the observer that sends replication to each new link; `SimClient`, given it too, adds `ClientPlugins`, `NetProtocol` and a `PredictionManager`, and spawns the client's entity. The server, `LocalServer`, the harness and the tests then add only what is theirs: the frame loop or a manual clock, a pace, a lobby or a restore. A headless app's frame is one constant of `net`.
- **U5. `thiserror` for every error.** Each error derives `Error` with an `#[error("…")]` on each variant and `#[source]` on each error it wraps, so `source` follows from the fields and no variant can drop its own. It is the established practice of Rust libraries, it cuts about 900 lines, and the workspace already builds it, as Bevy and Lightyear depend on `thiserror` 2. `common`, which takes no `thiserror` ([Modules](02-engine-core.md#modules)), derives `NotHex`'s `Display` and writes its empty `Error` impl by hand. `package`'s problem enums are errors too: a problem is the source of the error that holds it, so `LoadError`'s source is its problem, and a problem that only holds another error is `transparent`.
- **U6. An error sits with the code that makes it.** In the `error.rs` of the module that makes it; one that several sibling modules make sits in the `error.rs` of their parent, the crate root at the top. So `net`'s `JoinError`, which `door`, `lobby` and `offering` make, stays at the root, and its six others go to their modules; `runner`'s go to `session`, `session_rules` and `slot_rules`; `script`'s to `script_host`; `server`'s to `opening` and `server_tls`; `verifier`'s to `replay`. `package`'s errors, which most of its modules make, become `error/`, with `ContentError`, `StoreError`, `LoadError` and `PackageRef` in `mod.rs` and each problem enum in a file of its own.
- **U7. `net` mirrors its two sides.** `sim_server/` holds `SimServer` in `mod.rs` and the 17 modules only the server uses: `bot_driver`, `checkpoint_thread`, `checkpoints`, `door`, `journal_watch`, `key_file`, `lobby`, `offering`, `receipts`, `seats`, `server_bots`, `server_dir`, `server_exit`, `server_setup`, `server_signer`, `session_dir` and `session_journal`; `sim_client/` takes `client_dir`. `local/` holds the singleplayer server's `local_pace`, `local_relink`, `local_server` and `local_session`, and `harness/` the in-process harness. What both sides use stays at the top: `events`, `faults`, `input_message`, `join`, `leave_match`, `match_clock`, `match_start`, `net_protocol`, `offer`, `order_script`, `pace`, `save_command`, `session_times` and `superseded`. A directory is named by the type in its `mod.rs`, so `server/` and `client/` are not used.
- **U8. One meaning for each name.** The renames:

  | Now | Then | Why |
  | --- | --- | --- |
  | `LocalMatch`, `local_match/` | `InProcessMatch`, `harness/in_process_match/` | "Local" names the singleplayer server |
  | `ServerData`, `ClientData`, `Snapshots` | `ServerDir`, `ClientDir`, `SnapshotDir` | "Data" names a package's file data; a layout of a directory is a `*Dir`, as `DataDir` and `SessionDir` are |
  | `net::Speed` | `PaceSpeed` | `capabilities::Speed` is a unit's |
  | `protocol::LoadError` | `LogLoadError` | `package::LoadError` is a package load's |
  | `net::SlowSync`, the log event | `JournalSyncSlow` | `store::SlowSync` is the writer's value |
  | `log::Level` | `LogLevel` | `capabilities::Level` is a unit's |
  | The LAN check's `Outcome` | `ProcessOutcome` | `protocol::Outcome` is a session's |
  | `items::Carried` | `ItemStack` | `stats`' `Carried` is a modifier's |
  | `deliveries::Reach` | `Reached` | `navigation`'s `Reach` is a cell's sets |
  | `store`'s two `Shared` | `AppendShared`, `LatestShared` | One for each writer |
  | `AreaEffect`, `ProjectileEffect`, `RevealEffect`, `SpawnEffect`, `ModifierEffect` | `AreasEffect`, `ProjectilesEffect`, `VisionEffect`, `ActionsEffect`, `StatsEffect` | A role takes its module's name |
  | `TracksColumn`, `SightColumn`, `UnitStateColumn` | `ProgressionColumn`, `VisionColumn`, `UnitsColumn` | The same |
  | `UnitStateCall`, `Draws` | `UnitsCall`, `ScriptsCall` | The same; `sim`'s public `Draws` is another type |
  | `PositionApi`, `position_api.rs` | `UnitsApi`, `units_api.rs` | The same |
  | `TagEffect`, `TagEffects`, `TagEffectStatus`, "tag effect" | `TagProperty`, `TagProperties`, `TagPropertyStatus`, "tag property" | It is what a tag gives, not an `Effect`: the term changes in the code, designs 04 and 08, the generated reference and the roadmap |

  Two names stay: `UnitOrder`, the orders' effect, and the order to a unit that 12 other places of the crate name; and `CoreApi`, the script API of the core, which is `units`, `scripts` and `players` and no one module, and which as `ScriptsApi` would stand one letter from the registry, `ScriptApi`. Each module has one type of each role, so the name follows from the module alone.
- **U9. One shape for each kind of file.** A public type that stands on its own has its own file: `SessionHeader`, `Applied` and `DurableHead` leave `session_log/mod.rs`, `TickHashes` and `PlayerLink` leave `sim_server`. Inline tests past 40% or 150 lines of their file move to `tests.rs`. The free `pub(crate)` functions become methods. A crate's log events are in `events/`, and its harness, the code only `internals` builds that reads no one file's privates, in `harness/`. The `lib.rs` lists take one path form, `pub use crate::module::Item`, the one a nested `internals` or `bench` module can also take.
- **U10. A message holds its own step, and a report all of them.** An error's message names only what failed at its own step, never its source's text, and a variant that adds no text is `#[error(transparent)]`: the Rust error-handling project group's guidance, which `thiserror` follows, so a tool that walks the chain shows each step once. A load error's message names its package, and its problem is its source. Every log, log event and panic writes an error through `log`'s `ErrorReport`, which joins each message down to the root cause with `: `, as `std::error::Report` writes one, so the logs read as before. A binding that holds an error the code writes is named `error`; a test of `log` reads the workspace's production code, and fails on an error written alone, as a `%` field, by `to_string` or in a format string, and on an `#[error]` message that writes its source. A crate without `log` panics with an error's `Debug`, which holds its sources. Rhai's `EvalAltResult` has no source, so its message is kept as a `ScriptError`'s, an exception the test lists; a `clap::Error` is the other (U12).
- **U11. `derive_more` for every other `Display`.** A type that is no error derives `Display` with `derive_more`: a newtype writes its inner value, and a struct or a variant its `#[display("…")]`, whose arguments may call a method. `derive_more` 2 is in the build already, with `display`, through Bevy and aeronet, and `common` takes it beside `serde`. Four stay written by hand, as each holds logic no format states: `Bytes32`'s hex, `FilterData`, `ErrorReport`'s chain, and `Num`, which pads its exact decimal to the formatter's width.
- **U12. `clap` reads every command line.** The client, the server, the verifier and the LAN check each derive `clap::Parser` on their `Args`, which takes each value through its `FromStr` where it enters: `SlotBotFile`, `CertificateHash`, `XOnlyPublicKey`, `SocketAddr`, `NonZeroU32`, and paths from `OsStr`. It is the established parser of Rust's tools, as cargo and fd use it; it gives `--help`, `--version` and a suggestion for a misspelt flag; and the workspace builds `clap` 4 already, through `criterion`. clap states the shape of a command line: a flag given twice, a missing value, an unknown flag, the `--data` that `--local` requires and the `--local` that `--server-bot` requires, and the client's four arguments of a remote server, required together unless `--local` is given and refused with it, so no command line changes. A rule of one value that its type does not hold is that value's parser, so its refusal also takes clap's text: the client's `--server-bot` refuses the client's slot 0 with `ServerBotError::ClientSlot`. The client's help writes its two forms, of a remote server and of `--local`, as clap's own usage writes one form only. `--help` and `--version` print to standard output, as the program's output and not a log, and exit with `ExitStatus::Success`, or with `Failure` when they do not print; a usage error is logged with `error!` and exits with `ExitStatus::Usage`, the code clap gives. One copy of this end serves the four binaries: `log`'s `Logging::command_line::<P>`, which gives the command line `P` reads, or the `ExitStatus` the binary exits with; `log` takes `clap`, and `common` for `ExitStatus`. clap writes its value parser's error into its own message, so a `clap::Error` is written by its own `Display` and not through `ErrorReport`, which would write that error twice. A parser on `lexopt`, which ripgrep 14 took to control its hundred flags, would leave the help, the errors and their tests to write by hand, as now; `bpaf` and `argh` are smaller, fewer tools use them, and `argh` takes no argument that is not UTF-8.
- **U13. One bench target for each crate, and criterion's filter chooses the cases.** A crate with benches has one `[[bench]]`, named for its module, `benches/<module>.rs`: its `criterion_group!` takes `bench::run`, the one function of `lib.rs`'s `bench` facade, which runs each bench function of the crate in turn. Criterion's own command line chooses the cases, as libtest's filter chooses tests: its filter, a regular expression over each case's id; `--exact`, for one id; and `--list`, for every id. So `cargo bench -p campfire-runner --features bench -- server_tick/mean_3v3` runs one case, `-- num/` every case of a group, and `cargo bench --workspace --features bench --bench '*'` every case of the workspace: `--bench '*'` takes only the bench targets, as each binary is a bench target too, whose libtest harness refuses criterion's flags. A parser of our own in front of criterion's would have to pass on criterion's flags, `--save-baseline`, `--baseline`, `--profile-time` and the rest, and give the cases a second name beside the id that criterion stores its results by. Each case sits in a group, and its id is `<group>/<case>`. A group's name is unique in the workspace, so a filter run over the workspace names the cases of one crate: `protocol`'s two cases join a `chain_head` group, as `chain_head/sign` and `chain_head/check`. Criterion calls a case's function only when the filter takes it, so a fixture that loads packages or starts a match is made in the first case that needs it, not before the group: a `LazyCell` holds one that the cases share and only read, as the runner's `Reference3v3`; an `Option` that the case fills with `get_or_insert_with` holds one that the case changes, as each of `net`'s walking matches, and the state it carries from one sample to the next stays as it is now. A fixture of plain values, the inputs of `math`, `sim`'s world of 300 units and the scenes of `collision`, reads no file and runs no tick, and stays as it is. CI runs each case once on every platform, with `cargo test --workspace --all-features --bench '*'`, criterion's test mode, on the crates the test step built, so it only compiles and links the bench targets: a case that panics, breaks a `debug_assert` or repeats a name in its group fails the run, as no check finds today. A group whose name a second group of the same target takes again fails nothing: criterion gives the second's case the id `<group>/<case> #2`. Each crate with benches sets `bench = false` on its library, as criterion's guide asks: a library is a bench target unless its manifest says not, and its libtest harness refuses criterion's flags, `--measurement-time` and `--baseline` among them, so `cargo bench -p <crate> -- <flag>` failed before it reached criterion. A case runs as it measures, each worst-tick case of `server_tick` and `server_stage` a whole match, so the step takes about 30 s in the dev profile ([Cost in CI](13-benches.md#cost-in-ci)), as a test would not: a shorter match in a debug build would prove only the pick and the first wave.

## Shared test helpers

- **Keys.** `protocol`'s `internals` gives `TestKey`: the key of one byte, and the key of byte 41 that the tests' servers sign with; every test takes its keys from it.
- **Directories.** Every test makes its directory with `tempfile::TempDir::new()`, removed when the test ends or panics, each with a name of its own. `ScratchDir`, `Scratch` and the five hand-made directories go.
- **Scripted matches.** `runner`'s `scripted.rs` holds `Aim`, the tick rate and the order builder that the proving match and the reference 3v3 share. Each keeps its own `cast`, as each builds its own plan type in a `const` script, which no trait method can.
- **A package's content.** `PackageContent` holds the list of its keys beside its fields, and a test checks that the two name the same keys; `package` takes the list from there.

## Tests

The renames, moves and splits are pure refactors: the tests that cover the code move with it and pass unchanged. What is new has its tests:

- Each 32-byte type, in one table: `Display` gives 64 lowercase hex, `FromStr` reads it back where there is one and refuses other text, and serde encodes the 32 bytes; a secret encodes its bytes too, and has no text form to test.
- `ExitStatus` gives 0, 1, 2 and 74; a failed snapshot still exits with 74.
- `SlotBotFile` parses `3=bot.toml`, and refuses a missing `=`, a slot that is not a number, and a script that does not read, each with its variant; each binary's command line refuses a missing value, an unknown flag and a flag given twice, each by its `ErrorKind`, and a value its parser refuses, with that parser's error as the source; the client refuses `--server-bot` without `--local` and a server bot in slot 0; the server takes its flags in any order; `--help` exits with 0, and a usage error with 2.
- The random key skips a secret that is not a valid key: a source whose first 32 bytes are zero gives the key of its next.
- `capabilities` checks the role names: every `Effect`, `ViewColumn` and `CallPart` of a module, and its script API, is named `<Module><Role>` in `<module>_<role>.rs`, but `UnitOrder` and `CoreApi`, which the test lists.
- `PackageContent`'s list of keys names exactly its fields.
- `ErrorReport` writes each error down to the root, a transparent step once; a `LoadError` writes its package, its problem and the error under it, each once; the workspace writes no error alone, and the test finds each way to write one, in a table of samples.
- Each crate's bench target lists its ids with `-- --list`, each `<group>/<case>`, and CI's bench step runs each case once. `--list` for the runner and for `net` makes no fixture, so it returns at once. The check chain's clippy, with `--all-targets --all-features`, builds every bench target.
- The net scenarios, the restore and checkpoint tests, and the LAN check pass unchanged, with the server's `--server-bot`.
