# Campfire — Structure and names

How the workspace lays out its files, names its types, and shares what more than one crate or binary needs: one rule for each kind of value, one place for each error, one name for each meaning, and one copy of each piece of wiring. The proposal changes no behaviour but one flag name, and every step but the first ones of the shared parts is a pure refactor. It comes from an audit of the workspace after [Storage and workers](11-storage.md).

## Today

The workspace keeps most of its own rules: no `foo.rs` sits beside a `foo/`, no production code uses `super::`, `pub(in …)`, a tuple return or a re-export outside `lib.rs`, and every crate of the deterministic core denies the same lints. What the audit found:

- **Values of 32 bytes.** Five types wrap `Bytes32`, with the same body and different derives: `StateHash` and `Fingerprint` in `common`, `SessionId`, `CertificateHash` and `SnapshotFingerprint` in `protocol`. `CertificateHash` has no `Hash`, only `Fingerprint` has `Ord`, and `Fingerprint` and `SnapshotFingerprint` have no `FromStr`. Five more wrap a bare `[u8; 32]`: `InputHash`, `SeedCommitment`, `ConnectChallenge`, `ServerSeed` and `SegmentSeed`. A delegation's id is a bare `[u8; 32]` in `Delegation::id`, `Receipt::delegation` and `DurableHead::delegation`, as are a delegation's `seed_contribution` and `sim`'s `TypeHash::hash`.
- **Exit codes.** The server's storage failure is a named `74`; a bad command line is a bare `2` in the client, the server, the verifier and the LAN check, six places. The client and the server each turn an `AppExit` into an `ExitCode`.
- **The binaries.** The client and the server each have `fill` and `unix_now`, a `BotFile`, a parse of `<slot>=<orders file>`, and a read of an order script from its file. The flag is `--server-bot` on the client and `--bot` on the server. Each `Args::parse` gives its error as a `String`. The loop that makes a random key is in the client and in `net`'s `KeyFile::read_or_create`.
- **App wiring.** Three places build a server's app, the server, `LocalServer` and the test harness, each with `ServerPlugins`, `NetProtocol`, `SimServer` and the same `ReplicationSender` observer; three build a client's, the client, the harness and the local server's test, each with `ClientPlugins`, `NetProtocol`, `SimClient`, a `PredictionManager` and the same client entity. A headless frame of 2 ms is written in three places.
- **Errors.** 65 error types write `Display` and `Error` by hand, 1,345 lines. They sit in two kinds of place: `net`'s `error.rs` holds seven errors, most of one module each, while three of its modules hold their own; `runner`, `script`, `server` and `verifier` keep every error at the crate root; `package`'s `error.rs` is 932 lines with 14 types.
- **Test helpers.** A key from one byte is written more than 15 times. Temporary directories are made three ways: `tempfile::TempDir`, `store`'s `ScratchDir` and `net`'s `Scratch`, and by hand from `env::temp_dir()` and the process id in five unit tests, which leave their directory when they panic. `runner`'s two scripted matches each define `Aim`, `TICK_HZ`, `order` and `cast`.
- **`net`.** 47 modules at the top: the client's are in `sim_client/`, the server's 17 lie flat beside those both sides share. "Local" names the singleplayer server (`LocalServer`, `LocalSession`, `LocalPace`, `LocalRelink`) and the in-process test harness (`LocalMatch`). "Data" names a package's file data (`ActionData`, `MapData` and 20 more) and a data directory (`ServerData`, `ClientData`).
- **Names.** Five public names mean two things in two crates: `Speed` (`net`, `capabilities`), `LoadError` (`package`, `protocol`), `SlowSync` (`store`, `net`), `Level` (`log`, `capabilities`) and `Outcome` (`protocol`, the LAN check). Three names mean two things in one crate: `Carried` and `Reach` in `capabilities`, `Shared` in `store`. In `capabilities`, five effect types take their module's name (`AbilitiesEffect`, `CombatEffect`) and five their subject's (`AreaEffect`, `RevealEffect`); two view columns take their subject's (`TracksColumn`, `SightColumn`); the units' API is `position_api.rs`; and `TagEffect` is not an `Effect`.
- **Files.** `session_log/mod.rs` is 1,831 lines and holds the public `SessionHeader`, `Applied` and `DurableHead`; `sim_server.rs` holds the public `TickHashes` and `PlayerLink`. Twenty-three files keep inline tests past 40% or 150 lines of the file. Eleven free `pub(crate)` functions remain. `sim`'s `Drawn` and `Variant` have no `Debug`. `capabilities`' `lib.rs` lists its layers without `items` and `books`, which the layer test holds. `runner` keeps 11 harness modules among its production ones, and its event and `verifier`'s sit at the crate root, while `net` keeps its in `events/`. The keys of a package's content are listed twice, as `PackageContent`'s fields and as `package`'s `KEYS`.

## Decisions

- **U1. One rule for a value of 32 bytes.** A public value wraps `Bytes32`; a secret, `ServerSeed` and `SegmentSeed`, wraps `[u8; 32]` and has no `Display`. Each is a type of its own, written by hand, in its own file with its own doc, and each has the same derives: `Debug`, `Clone`, `Copy`, `PartialEq`, `Eq`, `PartialOrd`, `Ord`, `Hash`, `Serialize` and `Deserialize`, serde transparent; `new` and `as_bytes`; `Display` as 64 lowercase hex for a public one; and `FromStr` only where text from outside names it, today `StateHash`, `SessionId` and `CertificateHash`. A generic `Hex32<Kind>` would let no crate but `common` give one its own methods, as `SnapshotFingerprint::of`, and a macro is not needed where plain code works. A delegation's id becomes `DelegationId`, its seed contribution `SeedContribution`, both in `protocol`, and `TypeHash::hash` a `Bytes32`.
- **U2. One enum of exit codes.** `ExitStatus` in `common`: `Success` 0, `Failure` 1, `Usage` 2 and `Storage` 74, each with its `code`. The values do not change: `2` is what `clap` and the shells give a bad command line, and `74` is sysexits' `EX_IOERR` ([D9](10-sessions.md#decisions)). It enters `common` as the verifier and the client, which do not depend on each other, both name it. `ServerExit::STORAGE_FAILED` goes; `net` turns an `AppExit` into an `ExitCode` once, for the client and the server.
- **U3. One copy of what the binaries share.** `net`, which the client and the server both depend on and whose setups take a clock and a source of entropy, gives the OS's: `fill`, from `getrandom`, and `unix_now`. `protocol`, which owns `secp256k1`, makes a random key from a source of entropy, for the client and `KeyFile`. `net` reads a bot of a server's: `SlotBotFile`, which parses `<slot>=<orders file>` and reads its order script into a `SlotBot`, each failure a variant of its error; and `OrderScript::read` for a script in a file. Both binaries name the flag `--server-bot`, as the client's `--bot` already names the client's own script; the server's `--bot` of [Server bots](10-sessions.md#server-bots) becomes `--server-bot`, and both take their flags in any order. Each binary's `Args::parse` fails with an `ArgsError` of its own cases.
- **U4. One copy of each app's wiring.** `SimServer`, given the tick's length, adds `ServerPlugins`, `NetProtocol` and the observer that sends replication to each new link; `SimClient`, given it too, adds `ClientPlugins`, `NetProtocol` and a `PredictionManager`, and spawns the client's entity. The server, `LocalServer`, the harness and the tests then add only what is theirs: the frame loop or a manual clock, a pace, a lobby or a restore. A headless app's frame is one constant of `net`.
- **U5. `thiserror` for every error.** Each error derives `Error` with an `#[error("…")]` on each variant and `#[source]` on each error it wraps, so `source` follows from the fields and no variant can drop its own. The enums and their messages do not change. It is the established practice of Rust libraries, it cuts about 900 lines, and the workspace already builds it, as Bevy and Lightyear depend on `thiserror` 2. Two stay written by hand: `common`'s `NotHex`, as `common` depends on `serde` alone ([Modules](02-engine-core.md#modules)); and `package`'s `LoadError`, whose source is the error inside its problem, which no attribute names. A problem enum that an error holds, and that is no error itself, keeps its own `Display`.
- **U6. An error sits with the code that makes it.** In the `error.rs` of the module that makes it; one that several sibling modules make sits in the `error.rs` of their parent, the crate root at the top. So `net`'s `JoinError`, which `door`, `lobby` and `offering` make, stays at the root, and its six others go to their modules; `runner`'s go to `session`, `session_rules` and `slot_rules`; `script`'s to `script_host`; `server`'s to `opening` and `server_tls`; `verifier`'s to `replay`. `package`'s errors, which most of its modules make, become `error/`, with `ContentError`, `StoreError`, `LoadError` and `PackageRef` in `mod.rs` and each problem enum in a file of its own.
- **U7. `net` mirrors its two sides.** `sim_server/` holds `SimServer` in `mod.rs` and the 17 modules only the server uses: `bot_driver`, `checkpoint_thread`, `checkpoints`, `door`, `journal_watch`, `key_file`, `lobby`, `offering`, `receipts`, `seats`, `server_bots`, `server_dir`, `server_exit`, `server_setup`, `server_signer`, `session_dir` and `session_journal`; `sim_client/` takes `client_dir`. `local/` holds the singleplayer server's `local_pace`, `local_relink`, `local_server` and `local_session`, and `harness/` the in-process harness. What both sides use stays at the top: `events`, `faults`, `input_message`, `join`, `leave_match`, `match_clock`, `match_start`, `net_protocol`, `offer`, `order_script`, `pace`, `save_command`, `session_times` and `superseded`. A directory is named by the type in its `mod.rs`, so `server/` and `client/` are not used.
- **U8. One meaning for each name.** The renames:

  | Now | Then | Why |
  | --- | --- | --- |
  | `LocalMatch`, `local_match/` | `InProcessMatch`, `harness/in_process_match/` | "Local" names the singleplayer server |
  | `ServerData`, `ClientData`, `Snapshots` | `ServerDir`, `ClientDir`, `SnapshotDir` | "Data" names a package's file data; a layout of a directory is a `*Dir`, as `DataDir` and `SessionDir` are |
  | `net::Speed` | `PaceSpeed` | `capabilities::Speed` is a unit's |
  | `protocol::LoadError` | `LogLoadError` | `package::LoadError` is a package load's |
  | `net::SlowSync`, the log event | `JournalSyncSlow` | `store::SlowSync` is the writer's value |
  | `log::Level` | `LogLevel` | `capabilities::Level` is a unit's |
  | The LAN check's `Outcome` | `ProcessOutcome` | `protocol::Outcome` is a session's |
  | `items::Carried` | `ItemStack` | `stats`' `Carried` is a modifier's |
  | `deliveries::Reach` | `Reached` | `navigation`'s `Reach` is a cell's sets |
  | `store`'s two `Shared` | `AppendShared`, `LatestShared` | One for each writer |
  | `AreaEffect`, `ProjectileEffect`, `RevealEffect`, `SpawnEffect`, `ModifierEffect` | `AreasEffect`, `ProjectilesEffect`, `VisionEffect`, `ActionsEffect`, `StatsEffect` | A role takes its module's name |
  | `TracksColumn`, `SightColumn`, `UnitStateColumn` | `ProgressionColumn`, `VisionColumn`, `UnitsColumn` | The same |
  | `UnitStateCall`, `Draws` | `UnitsCall`, `ScriptsCall` | The same; `sim`'s public `Draws` is another type |
  | `PositionApi`, `position_api.rs` | `UnitsApi`, `units_api.rs` | The same |
  | `TagEffect`, `TagEffects`, `TagEffectStatus`, "tag effect" | `TagProperty`, `TagProperties`, `TagPropertyStatus`, "tag property" | It is what a tag gives, not an `Effect`: the term changes in the code, designs 04 and 08, the generated reference and the roadmap |

  Two names stay: `UnitOrder`, the orders' effect, and the order to a unit that 12 other places of the crate name; and `CoreApi`, the script API of the core, which is `units`, `scripts` and `players` and no one module, and which as `ScriptsApi` would stand one letter from the registry, `ScriptApi`. Each module has one type of each role, so the name follows from the module alone.
- **U9. One shape for each kind of file.** A public type that stands on its own has its own file: `SessionHeader`, `Applied` and `DurableHead` leave `session_log/mod.rs`, `TickHashes` and `PlayerLink` leave `sim_server`. Inline tests past 40% or 150 lines of their file move to `tests.rs`. The free `pub(crate)` functions become methods. A crate's log events are in `events/`, and its harness, the code only `internals` builds that reads no one file's privates, in `harness/`. The `lib.rs` lists take one path form, `pub use crate::module::Item`, the one a nested `internals` or `bench` module can also take.

## Shared test helpers

- **Keys.** `protocol`'s `internals` gives `TestKey`: the key of one byte, and the key of byte 41 that the tests' servers sign with; every test takes its keys from it.
- **Directories.** Every test makes its directory with `tempfile::TempDir::new()`, removed when the test ends or panics, each with a name of its own. `ScratchDir`, `Scratch` and the five hand-made directories go.
- **Scripted matches.** `runner`'s `scripted.rs` holds `Aim`, the tick rate and the order builder that the proving match and the reference 3v3 share. Each keeps its own `cast`, as each builds its own plan type in a `const` script, which no trait method can.
- **A package's content.** `PackageContent` holds the list of its keys beside its fields, and a test checks that the two name the same keys; `package` takes the list from there.

## Tests

The renames, moves and splits are pure refactors: the tests that cover the code move with it and pass unchanged. What is new has its tests:

- Each 32-byte type, in one table: `Display` gives 64 lowercase hex, `FromStr` reads it back where there is one and refuses other text, and serde encodes the 32 bytes; a secret encodes its bytes too, and has no text form to test.
- `ExitStatus` gives 0, 1, 2 and 74; a failed snapshot still exits with 74.
- `SlotBotFile` parses `3=bot.toml`, and refuses a missing `=`, a slot that is not a number, and a script that does not read, each with its variant; each binary's `ArgsError` covers a missing value, an unknown flag and a flag given twice; the server takes its flags in any order.
- The random key skips a secret that is not a valid key: a source whose first 32 bytes are zero gives the key of its next.
- `capabilities` checks the role names: every `Effect`, `ViewColumn` and `CallPart` of a module, and its script API, is named `<Module><Role>` in `<module>_<role>.rs`, but `UnitOrder` and `CoreApi`, which the test lists.
- `PackageContent`'s list of keys names exactly its fields.
- The net scenarios, the restore and checkpoint tests, and the LAN check pass unchanged, with the server's `--server-bot`.
