# Slice: The debug loop

At its end, a wrong play names its cause in its first run: the Zero Hour check fails at the tick and unit where an invariant breaks, or names the count of orders no unit took, and prints each unit it is asked for as a readable table; a moved golden names the units that moved first. The measurements are in [The debug loop](../research/debug-loop.md).

## Decisions

- **An invariant of state is an output assert.** A decision that says what a pass leaves, as [A walker never stays in a static body](04-capabilities/navigation.md), gets a `debug_assert!` at the end of the system that keeps it, naming the unit and its place, as a logic error crashes. Refused: a warning, which a play of thousands of ticks repeats each tick; a test alone, which only its fixture's case reaches.
- **What a play drops is counted.** The orders capability records each unit's drop of an order, by cause, and whether any unit of the order took it, in a report, outside the state, so no hash moves; the check counts each order a bot's search left unsent, by `OrderUnsent`; each play prints both, and `golden.toml` pins them, as an attack that no unit takes shows only as a count. Refused: a log line for each, as `sim` and `capabilities` log nothing ([Typed log events](02-engine-core.md#testing-and-diagnostics)); the check's sink that drops them, as now.
- **One probe of a match.** The harness's `MatchProbe` writes, at a period, for each player slot the counts of its units idle, walking, stuck, working, fighting and acting, then a line for each unit it selects: stable id, type, player slot, team, place, what it does, its target, destination, route goal, ticks stuck and life, as an aligned table; a test asserts on its lines, and the check writes one for `--probe <play>:<period_ms>:<units>` through `store`. A walker idle in it is one steering takes as an idle friend, and its stuck is the walker's own threshold, which `Progress` holds for both. Refused: a dump edited into a play and removed after, 24 of the session's 34 check runs; Bevy's remote protocol or an inspector, a new dependency, for a check that runs with no window.
- **One play at a time.** The check's `--play <name>` runs the plays it names, after the import, and refuses a probe of a play it does not run, or two of one play. Refused: a reuse of the last import, which plays a package the importer no longer writes when the change is the importer's.
- **A `Num` reads as a decimal.** `Num`'s `Debug` prints the shortest decimal that reads back to its bits, as Rust prints a float (`flt2dec`'s shortest mode), so a `Vec3` prints `999.8` and not `Num(16773965824)`; `Display` stays exact. Refused: the bits, which a reader divides by 2²⁴; `Display` as `Debug`, whose 24 digits a table cannot hold.
- **Tests and checks name Bevy's types.** `sim`'s `internals` turns on `bevy_ecs/debug`, so a B0001 panic and an archetype name each type; a shipped build keeps it off. Planned: a schedule test that shuffles the unordered systems by `shuffle_seed`, as the archetype shuffle moves units ([The archetype shuffle](02-engine-core.md#testing-and-diagnostics)).
- **A golden says what moved.** Beside each golden record, `<name>.units.txt` holds a sample of the match every 300 ticks, 10 s at 30 ticks a second, so the shortest golden match, of 600 ticks, holds two: a line for each unit, its stable id, type, team, player slot, place, pools and death, then each player's resources, the parts of units and players the behaviour digest hashes, as a tick's deaths show as units dead or gone and its failed calls in the digest alone; a moved golden names the first sample and each line that differs, and a bless's diff shows them, as Factorio's heavy mode writes its states as tagged text that a diff tool compares. Refused: a sample every 1,000 ticks, the replay test's checkpoint period, which the lane and proving matches never reach past their start; a build of the base commit on each failure, a second build of the whole workspace; hashes by state type, which name a type and not a unit.
- **A rule's case starts from its setup.** Each rule the 3v3 showcase asserts, a cast, a camp, gold, learning, starts from the units its case places, in a short match of its own, as Factorio's integration tests place a few objects on a small map; the scripted match keeps the goldens, the replay and the match's end. Refused: the showcase as now, whose case of Eruption failed when a pathing change moved Rime; a case that asserts what some unit of the long match did, which passes a rule that is wrong. This changes [One scripted match for each mode](02-engine-core.md#testing-and-diagnostics): a new rule joins its mode's cases, and its scripted match only when it changes the match.
- **Named pins.** A test pins what a bot sent as the orders it decodes, typed values that a failure prints by their names, not as the bytes of their payloads.
- **A drawn tick, planned.** The probe draws a tick of a play as an SVG of the map, its walls, bodies and units by team, when a cause needs a picture, as Factorio's developers read a desync from the screenshot of its tick.

## Checks

- **The session again.** With each of the session's fixes taken out in turn, in a worktree, one run of the check names its cause: without `stand_clear`, the assert of a walker in a static body at its tick; without the bots' search by the order's own test, the count of ignored attack orders; without the attack that goes on as the army falls, the probe's line of the army idle away.
- **Costs.** The suite keeps 30 s.
