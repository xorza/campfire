# Skirmish bots

A proposal for one slice. When it ends, each lasting decision moves into the document of the system it governs, and this document is deleted ([A slice's proposal is temporary](../../AGENTS.md#documents)); its plan is in `PLAN.md`. Its facts are in [Test matches](../research/test-matches.md), Skirmish bots that play a whole match.

**At the slice's end** the user watches two Zero Hour bots, China and America, on Tournament Desert from standard starts: each builds its base, trains, and attacks when its army is ready, until one side's last building that counts falls; and the user plays a match of their own against such a bot. A bot plays the same from a base start, which stays a choice of the seat, whoever holds it.

## Decisions

### Bots

- **A bot is a Rhai script of its game, which the server's bot driver runs.** A game's rules package ships its bots as scripts of a role of their own, `bot`, which the driver calls outside the sim, as bots send inputs ([Game scripting](03-game-scripting.md), Bots send inputs): their orders become the seat's signed `Bot` inputs, so a replay and a verifier run no bot, as Dota 2's bots are Lua scripts at the server level and Spring's native AIs send commands as a player's. Refused: a bot inside the sim, as 0 A.D.'s Petra and Spring's Lua AIs run, which every peer would pay for and the sim's tick budget would hold; a bot of engine code that data configures, as Zero Hour's `AISkirmishPlayer` and OpenRA's `ModularBot` are, which names a game's ways in the engine ([Control](04-capabilities/control.md), A skirmish bot of rules, planned).
- **A bot decides from what it sees, each think.** The driver calls a bot's `on_think` every `think_ms` of its game's data, the seats staggered, as 0 A.D. shifts its AI players out of phase; the bot reads only what its team sees and its own player's resources, and orders only its own units, as Dota 2's bots. It holds nothing from one think to the next, so a restore plays a bot on from the world it finds, as it plays an order script on from its tick. Refused: a table a bot keeps between thinks, which each checkpoint would save and a restore give back, as OpenTTD's script AIs save theirs and OpenRA's modules their squads and timers, as no behaviour this slice needs one.
- **A bot orders by the order scripts' directives.** A bot's call gives the same directives, by the same names, that an order script gives, which one exhaustive map turns into a command ([Control](04-capabilities/control.md), A directive is generic over its references). Refused: a bot API of its own orders, which a new directive would leave behind.
- **A bot finds a building's place as the build tests it.** The bot API's search for a build's place walks a grid round a point, as `room_near` does, and takes the nearest point where the build's own placement holds for the bot's builder, so the order it gives passes, as OpenRA's base builder takes a cell in a ring round its yard. Refused: `room_near` alone, which tests a spawn's room and not a build's rules; Zero Hour's `SkirmishBuildList`, each building's place round the command center turned to the start, which the import would convert for each faction with a search behind it where a place is blocked.
- **A mode names its bots.** A mode's data lists its bots, each a script and its params, and a host gives a seat one of them by its name: `--server-bot <seat>=<bot>`; a seat of exact inputs at ticks takes an order script by `--server-orders <seat>=<file>`. Refused: a bot by its file's path, which a host must find in a package; one flag for both, whose value a parser must guess.
- **Order scripts stay as test fixtures.** An order script of inputs at ticks stays what the net tests, the check's plays and the client's `--bot` play, as a test's inputs must not depend on what a bot sees; the sample order scripts of `source/bots/` go, as a game's bots replace them. Refused: order scripts as Rhai bots, which put a script host under every test's inputs.

### Zero Hour

- **A builder and an attacker.** The Zero Hour rules package ships one bot script, which its mode data names twice: `builder`, which builds each building of its faction's base list that it lacks and does nothing once its base is whole, so on a base start it idles until a building falls and then builds it again; and `attacker`, which does what the builder does, trains its army from its producers, and sends the army at the nearest enemy start once it is as large as its param `army`, attacking the nearest enemy it sees there, as OpenRA's squad manager attacks with `SquadSize`; while it gathers, its army attacks the nearest enemy it sees within its param `guard` of its start, as OpenRA's `ProtectOwn` sends idle units at an attacker. Either plays from a standard start or a base start. Refused: a file for each faction and start, as an order script must be; behaviours by a timeline, whose waves the defenses wear down as fast as they come ([Test matches](../research/test-matches.md)); a random bonus to the army's size, as OpenRA draws one for each squad, which a seeded draw would need to repeat; no defense, under which an enemy at the base's edge meets no army.
- **The base list is the base start's.** The builder's list is the faction's `base_buildings_<faction>`, which the import writes for the base start, so the base a builder completes and the base a seat starts with are one ([Zero Hour](09-zero-hour.md), A base start). Refused: a build list of the bot's own, as Zero Hour's `AIData.ini` gives one, a second list to keep beside the import's.
- **A bots' match that ends.** The Zero Hour check plays two attackers from base starts until one side's last building that counts falls, and a builder against an attacker from standard starts, and pins each match's end; the builder of the skirmish play stays an order script of the check, a fixture.
