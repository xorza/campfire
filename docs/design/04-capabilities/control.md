# Control

## Mechanism

- **Orders and characters start the same actions.** `orders` runs units that take orders, `character` units a player drives; both start actions through the one pipeline ([Actions](actions.md)).

## Orders

- **Every capability's orders are its commands.** Each capability decodes and applies its own orders in Inputs, in the module list's order, those of `orders` last, so a buy and a cast of the bought item in one tick both apply; players, bots and AI issue the same orders.
- **A given order is an event.** `orders` gives every order of every source and triggers `UnitOrdered` for it, which each capability that keeps a loop of the unit's observes to set or end its own, production its build and gather, interaction the use slot; so `orders` writes no part of theirs. Refused: `orders` writing production's and interaction's parts, which tied it to both crates; and each capability decoding its own build, gather and use commands, which changes the command protocol and the order of two orders to one unit in a tick. As Bevy's observers carry a change to the systems that own what it touches.
- **A group is one command.** An order goes to the units its player commands, each its player controls carries it out, and a move of many shares one route ([Groups](navigation.md#groups)).
- **A player's orders go to its commanded units.** Each player holds the units its orders command, which a select sets, and an order names no units of its own, as Zero Hour's `MSG_CREATE_SELECTED_GROUP`, Spring's `NETMSG_SELECT` and StarCraft II's selection deltas set the units each command goes to ([The size of an order to a group](../../research/order-size.md)); an order to the units it commanded last sends no ids again. Refused: the ids in each order, whose size grows with its group and its ids, under any bound; the client's split of a group order, which plans one route for each part ([One command, one route](navigation.md)).
- **A select is the players' command.** A payload's command goes to a capability or to the players, who read a select in Inputs before any capability reads its orders, so production's and items' orders need no `orders` module. Refused: a select among `orders`' directives, which every mode of production would need; a capability that is no module.
- **An order goes to the units commanded at its place.** Each order of a tick goes to the units the last select before it set, in the order of the inputs and of their commands, so a select and an order in one input, or a select between two orders of one tick, commands what its client meant; the commanded units the tick ends with are the player's state. Refused: every select of the tick first, which sends an order before a later select to the later units.
- **A select holds what its player controls.** A select keeps, in increasing stable id, each unit it names that the match holds and that its player controls, a dead one among them, as a dead hero still learns, a leader as its order expands it ([An order to a leader is its spawns' order](control.md)), so what a player commands is bounded by its units; a select past one payload continues in the next input, which adds to it. Refused: every id a client names, which grows without bound.
- **A select goes with each order until its sender knows the server commands those units.** An input the server logs early never takes effect (`Applied::Early`), so an order sent after a select it never applied would command the units before it; the client leaves the select out only when its inputs' acks say the server applied a select of the order's units and no select it sent waits for its ack, and a bot or a script, which reads no ack, sends it each time. Refused: a select when the units differ from those sent last, which a select the server never applies turns into an order to other units; a select for every change of the client's selection, which logs a player's every click.
- **An order to a leader is its spawns' order.** `orders` puts a leader's living spawns in its place among an order's units, in increasing stable id, so a move of the mob shares one route and an attack sends each member, as OpenRA's port of the mob gives its members the nexus's move, attack, attack-move and stop, and Zero Hour's members take the nexus's victim; an idle member scans as its type declares, as the game's members acquire when idle ([A unit may lead its spawns](production.md)). Refused: the nexus's harmless weapon, which the game's members follow; a member's own following loop; `Squirrelliness`, a draw for each member each half second, of which the idle scan keeps the effect.
- **An unseen target is ignored.** An order's unit target must be one its player's group sees as it applies, so a stable id never tells a client what its group does not see ([Replication audiences](../10-replication-audiences.md)).
- **A player out of play gives no orders** when players out of play see what a spectator sees, as an order would act on what its group does not see.
- **A blocked order waits** and runs when the block ends.
- **A stop spends nothing.** A stop ends what a unit has under way with nothing spent; a train queue stays.
- **Order queues, `hold` and patrol are planned,** with the jungle leash as data, each with the slice that needs it.
- **An idle unit scans for a target, as its type declares.** A unit type's `acquire = { scan_ms, targets }` makes a unit that stands idle, with no destination, nothing under way and no attack target, take as its attack target, each `scan_ms` and staggered by stable id as `on_think` is, the nearest unit its team sees, center to center, that one of `targets` selects and that the first of its weapons that selects it reaches, the lower stable id at one distance. Practice: Zero Hour's `getNextMoodTarget`, as a human player's unit runs it, and OpenRA's `Defend` stance, a human player's default ([Zero Hour automatic attack](../../research/zero-hour-auto-attack.md)). Refused: a Rhai `on_think` for each unit, which an army of hundreds of idle units would call at each scan; a range of the scan's own past the weapons' reach.
- **A scanned target holds only in reach.** An attack target keeps its source, an order or the scan; the chase walks to an ordered one and drops a scanned one that no weapon of the unit reaches any more, for a unit that walks or stands, so it scans again at its next turn. Practice: Zero Hour fails a human player's attack of `CMD_FROM_AI` out of its pursuit, and OpenRA's `Defend` attacks without moving. Refused: a chase of a scanned target, which a bot gives by its orders where its game wants one.
- **The scan is the server's.** Only a role that computes state scans; a predicting client takes the target from the server's state and corrects to it. Refused: a client's own scan, which reads the enemies at their interpolated places, behind the server's, and so mispredicts anyway.
- **An army attack-moves.** The orders gain `attack_move`: each unit walks to a point and attacks each enemy its own weapons hit on its way, as Zero Hour's AI moves by `aiAttackMoveToPosition` and OpenRA's squads by `AttackMove` alone, and a bot sends its army so; a player's key for it in the client is planned. A unit the scan stopped walks on once its target is gone, and one that stands unstopped ended its walk. Near its target an army attacks by an order, as Zero Hour's scan passes over structures ([Test matches](../../research/test-matches.md)). Refused: an attack order to the whole army, which goes to one target and is dropped by each unit whose weapons do not hit it; an attack order for each unit, which costs an input each and needs the bot to know each weapon's targets; an attack of a filter in which each unit takes its own target, which changes that order for every bot and order script.
- **A unit that scans neither builds nor gathers.** The load refuses `acquire` on a type with no weapon, and on one with a build or a gather, whose loops stand a unit idle between their steps. Refused: a test of each capability's loop in the scan, which would tie `orders` to `production`.
- **Stances, planned,** with the slice that needs them: a player's choice of a unit's stance.
- **A directive is generic over its references.** Each directive type names its units, slots, places, item types and carried stacks through `OrderRefs`, ids by default, a stack by its slot in a command and by its item type in a bot's script, which finds its first stack as the order goes out: a command carries the ids, a bot's script the names, and one exhaustive map for each type gives the one for the other, so a variant added to a directive reaches the scripts with no list of its own. Refused: a named copy of the directives in `bots`, which a new variant leaves behind; the script's own keys, which named a part of the orders.
- **A bot's script names what it orders.** A slot by its action's name, found as the order is due among each commanded unit's slots, as a grant or an item moves them, as Dota 2's `GetAbilityByName`; a target by a filter, the nearest living unit it selects from the order's first unit of those its team sees, as an order aims only at those, as Dota 2's `GetNearbyCreeps`; a place by a marker's name, which its map holds once, as OpenRA's `Map.NamedActor`, or by its coordinates. Refused: slot places and stable ids, which hold only for one spawn order; a slot found at the load; a marker by its tag and place.
- **A bot orders by the order scripts' directives.** A bot's call gives the same directives, by the same names, that an order script gives, which one exhaustive map turns into a command (A directive is generic over its references). Refused: a bot API of its own orders, which a new directive would leave behind.
- **A bot's search runs its order's own test.** A unit a bot names by a filter is the nearest one the filter selects, its team sees, and its order takes by the test of the capability that checks the order, as each reference to a unit names what the unit is to its order: an attack's target one of the order's units may attack, a living enemy one of its weapons selects (`ActionSlots::may_attack`); an action's target one its start takes (`Action::start_target`), or a node its gather takes (`GatherView::gathers`); a use's object one the user may use; a shop one that serves the unit; a build's site one of its building and its player; a rally's any. Zero Hour's AI searches by `getAbleToAttackSpecificObject`, the test its attack command takes (GeneralsX, `PartitionFilterPossibleToAttack`, `ActionManager::canAttackObject`), and OpenRA's bot keeps the enemies its attacks hold a valid weapon for ([SquadManagerBotModule.cs](https://github.com/OpenRA/OpenRA/blob/bleed/OpenRA.Mods.Common/Traits/BotModules/SquadManagerBotModule.cs), `FindEnemies`). Refused: the nearest unit the filter selects, which may be one no order takes, so the army stands by a unit of no life ([Test matches](../../research/test-matches.md)); a test of life alone, which still aims at a living unit no ordered weapon selects.
- **An attack goes to the units that may attack its target.** A bot's attack of a filter goes to those of its units whose weapons select the target its search found, by the test of the attack order (`ActionSlots::may_attack`), and its other units attack-move to the target's place, whose scan takes what their own weapons hit, as OpenRA's squad finds its target by its leader's valid weapons (`SquadManagerBotModule.FindEnemies`) and attack-moves each unit not busy attacking, whose own targeting takes what its weapons hit (`GroundStates.cs`), and Zero Hour's group attack orders each member at the target, a member that cannot attack it going idle (`AIGroup::groupAttackObjectPrivate`). Refused: the attack to every unit, which the orders drop for each unit no weapon of which selects the target, so a tank under a helicopter stands think after think; each unit its own target (An army attack-moves); a test of each unit in the bot's script, a function of the script API for what the search already tests.
- **A bot finds a building's place as the build tests it.** A build order's place may be a search, `{ near, gap, steps }`, which the driver makes as the order goes out: it walks a grid round the point, as `room_near` does, and takes the nearest point where the build's own placement holds for the builder, so the order it gives passes, as OpenRA's base builder takes a cell in a ring round its yard; one that finds none goes unsent, and the bot orders again in a later think. A script's call reads only the script view, and the placement reads the world's units, fog and walls, so the search is the order's and not a call's, which an order script may name too. Refused: a call that returns the place, as Spring's `ClosestBuildPos`, which needs the world inside a script's call; `room_near` alone, which tests a spawn's room and not a build's rules; Zero Hour's `SkirmishBuildList`, each building's place round the command center turned to the start, which the import would convert for each faction with a search behind it where a place is blocked.
- **Order scripts stay as test fixtures.** An order script of inputs at ticks stays what the net tests, the check's plays and the client's `--bot` play, as a test's inputs must not depend on what a bot sees; the sample order scripts of `source/bots/` go, as a game's bots replace them. Refused: order scripts as Rhai bots, which put a script host under every test's inputs.
- **The scan reaches by any weapon.** An idle scan takes the nearest target that a weapon of the unit selects and reaches, where it takes the first weapon's reach today. Refused: the reach of the weapon the choice would take, which depends on readiness the next tick changes.
- **Retaliation is the mode's data.** The mode's `[retaliation]` gives the aggressor's filter and its most distance from the damaged unit, the radius round the damaged unit its allies answer within, and how long they chase; a type's `retaliate = { leash, reach }` makes its units answer, which the load refuses on a type of no weapon or no walk, as `RetaliationFriendsRadius`, `MaxRetaliationDistance` and `GuardChaseUnitsDuration` are `AIData.ini`'s and an immobile or `CANNOT_RETALIATE` object does not answer. Refused: a Rhai hook for each hit, called by every damage of a battle; OpenRA's return fire, which only the damaged unit answers.
- **A damaged unit calls its idle allies.** Once a tick's damage applied and its dead died, in Resolve, on the server, by the hits a report of `units` keeps, each unit damaged by a living aggressor its filter passes within its distance calls each living unit of its own player's allies, its own included, within the radius past its body, that answers, stands idle as the scan's idle, and has a weapon that selects the aggressor; each takes the aggressor as its attack target, dead or not the damaged unit, as `ActiveBody::attemptDamage` calls even as it dies. The pass visits the units damaged that tick alone.
- **A retaliation's target is chased to its leash.** A target of retaliation is chased as an ordered one is, and dropped when the chase's time passes, when the target lies past its `reach` from the point the unit stood at, or when the unit lies past its `leash` from it; then the unit attack-moves back to that point, as `AIGuardRetaliateReturnState` returns to its guard point. Refused: an ordered target, chased with no end; a scanned target, dropped past the weapons' reach, which leaves the unit standing under artillery.
- **Every player's units answer** (decided 2026-10-28). A bot's units retaliate as a player's, where Zero Hour's computer players' do not, as the engine's bot units scan only what their weapons reach, as a human player's, and would stand under fire past it. Refused: a human player's units alone, which leaves a bot's army that a scan of Zero Hour's AI would send after its attacker.

## AI

- **AI thinks in staggered turns.** `on_think` runs every `think_ms`, staggered by stable id; a unit whose call finds the think budget spent stays due, so under load AI thinks later and no unit loses its turn.
- **AI sees the stage's start.** Every call of a tick's Think sees the units as the stage began, and queries sort by stable id.
- **AI orders only its own unit,** checked as queued and applied when the call returns.
- **A reset as a jungle monster's.** `order_reset` walks a unit to its spawn, taking no order on the way, and refills it as it arrives, as League of Legends' jungle monsters hard-reset.
- **An avatar has no AI.** A player controls it, and a bot plays it through player inputs.
- **A bot gathers.** A bot sends each idle gatherer of its own to the nearest node and trains gatherers until it holds a count for each drop-off, as OpenRA's `HarvesterBotModule` orders each idle harvester to harvest and builds one while it holds fewer than 4 or than its refineries, and Zero Hour's AI wants a count of trucks for each supply center by difficulty, the free one besides ([Test matches](../../research/test-matches.md)). Refused: an engine rule that sends an idle gatherer to gather by itself, which decides for a player, as Zero Hour forces the wanting state on the AI's trucks alone; money for tests past the game's choices, under which no economy runs.

## Character

- **One input frame a tick, predicted.** Planned: a player drives a unit with one input frame a tick, keys, view angles, buttons and the tick its screen showed; a capsule controller moves it, and its client predicts it with the same code.

## Choices

- **Choices before the spawn.** A mode declares what players choose, a hero, a class, a faction or a loadout, each from avatars, loadout entries or values its data lists, unique or not; a choice of listed values takes one, which a session's host may pick for a player slot before the start, as Zero Hour's and OpenRA's lobbies give each player a faction ([Sessions](../08-sessions.md#decisions)); the choices are state, and a unit a player owns plays on the player's team, so it names the player's vision group.

## Network

- **A client predicts what its player drives and the start of its orders;** the rest is interpolated.
