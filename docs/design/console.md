# Console

A slice's proposal. At its end, an agent in Claude Code starts a local match of the MOBA test mode in the client, runs it paused to a tick, tables its units and shows a screenshot of one of them, while the user watches the window. Its plan is `PLAN.md`'s Console; when the slice ends, its lasting decisions fold into `02-engine-core.md` and `08-sessions.md`, its planned ones into `03-game-scripting.md`, `05-protocol-spec.md` and `06-script-api.md`, and this document goes. The facts are [The console](../research/console.md).

## Decisions

### Processes

- **The word is console.** What a tool outside a game's process asks of it is its console, as Factorio's, Source's and Unreal's consoles take commands from outside the match and RCON is a remote console. Refused: control, the relation of a player to its units; remote, the other end of a link; tether and helm, which no engine uses.
- **One MCP server starts the games.** `campfire-mcp`, a stdio MCP server that Claude Code starts from the repository's `.mcp.json`, starts the client and the server as its children and serves the tools of both, so it outlives their rebuilds, as `bevy_brp_mcp` starts its app. Refused: an MCP server in each game over HTTP, two endpoints of a token each, whose link to Claude Code drops at each rebuild; the Bevy Remote Protocol, whose reflected writes pass the log and which names Bevy's types, not the game's.
- **The official SDK.** `campfire-mcp` serves MCP through `rmcp`, on a runtime of one thread, and `tokio` stays in that crate. Refused: a JSON-RPC of our own on `codec::Json`, whose negotiation of the spec's revisions, which changed its handshake in 2026, would fail in silence.
- **The MCP server never builds itself.** `game_start` builds the client and the server through a command of the driver, its output into the MCP server's log, then starts the built binary with its console, as `cargo drive` holds a step's standard streams; `.mcp.json` names the `campfire-mcp` that `cargo drive run mcp` builds, and a reply says when the binary on disk is newer than the process. Refused: a build of itself, which Windows refuses over a running binary; a step of the driver that passes its streams through, a change of another repository whose build would hold the server's start past Claude Code's wait; a setup of each machine by `claude mcp add`, which no review sees.
- **The console ships.** `--console` is in every binary `cargo drive package` builds: its pipes reach only the parent, which already holds the process, and a client holds only what its server sends, so it reaches nothing a cheat could not, as Source and OpenRA ship their cheats behind a switch of the server. Refused: a feature of its own, a second gate beside `internals` (02-engine-core.md, One test feature), under which `release-dev` and the release build apart; Unreal's console, stripped from shipping builds, which would keep an agent's bot from shipping.
- **A game stops as its console's input ends.** The end of a game's standard input is a stop, as its first stop signal is, and `campfire-mcp` stops its games as MCP's stdio stops a server, their input closed, then a wait, then the OS's termination, so a game outlives no MCP server Claude Code ends, as MCP names the end of input the one portable stop. Refused: a game that runs on with no console, a window the user must close by hand; a group of processes or a job object of each OS, which `platform` would hold for what the closed pipe already says.
- **A game's end answers its calls.** A game that exits fails each call it has not answered, with its exit status and the last errors of its log, and `game_start` returns as the game's first line comes, before its load, which `sim_status` then reports. Refused: a call that waits on a game that is gone.

### The protocol

- **A game's console is its standard streams.** `--console stdio` makes a client or a server read requests from its standard input and write replies to its standard output, a JSON line each, the framing of MCP's stdio, its log staying on standard error; only the parent holds the pipes, so nothing listens on a port, as MCP advises a local server. Refused: a local socket, which needs an entity of `platform` for each OS and reaches a game another process started, planned when an agent needs to join a game it did not start; the network stack, planned for a remote server's admin.
- **One console protocol, in a problem crate.** `campfire-console` holds the requests and the replies, with `serde` and `schemars` and no Bevy, so `campfire-mcp` builds without the sim. Refused: postcard frames, which hold no schema, so two builds would read each other wrong in silence; the types in `host`, which puts Bevy and the sim in the MCP server's build; in `protocol`, which mixes a local tool into the specification others implement.
- **A console opens with its fingerprint.** A game's first line names its role and a fingerprint of the console's types, and `campfire-mcp` refuses a game of other types with a reply that says which to build again, as each outlives the other's builds.
- **A request carries its id, and a reply its tick.** Replies come in any order, matched by id, so a read answers between two ticks of a run that has not returned, as Claude Code calls read-only tools in parallel; each reply names the tick its world held, the last tick ended. Refused: one request at a time, which holds every read behind a run.
- **A line that is no reply is logged.** `campfire-mcp` writes a line of a game's output that decodes as no console message to its log and reads on, as a dependency's print would break the stream, and an id matches no stray line. Refused: a console that stops at the first such line, which a crate's print ends; standard output moved to another descriptor, an entity of `platform` for each OS.
- **Events come over the console.** A game sends each log event as it logs it, and `campfire-mcp` keeps the latest of each game in a ring of fixed size, which `game_events` reads by level, target and tick. Refused: the log file read back, a disk read of what the process already held.

### Tools

- **Tools by outcome, by what they act on.** `game_` starts, stops and reads the processes, `sim_` the match and `view_` the client's window, each with a title; `tools/list` keeps one order, a unit is named by its type's name beside its stable id, and an unknown name fails with the names nearest it, as Anthropic's guide and MCP's revision of 2026-07-28 advise. Refused: a tool for each request of the console, which leaves the agent to compose them.
- **The instructions say the loop.** The server's instructions, which Claude Code loads as a session starts while the tools wait for its search, name what the tools are for and the loop they make, a game started paused, run to a tick, read, then shown, within 4,096 characters, and each description leads with the words a search would match. Refused: the loop told in each tool's description, which the search reads one at a time.
- **Hints say what a tool changes.** A read, `sim_status`, `sim_units`, `game_events` and `view_screenshot`, has `readOnlyHint`; a call that a repeat leaves as it was has `idempotentHint`, a run to a tick, a pace, a camera set and a stop among them. Refused: no hints, under which Claude Code calls every read one at a time.
- **A result is one text block, and an image when it shows one.** A tool gives the agent its text, a table as the probe aligns it, in one text block, beside a screenshot's PNG, and declares no `outputSchema`. Refused: `structuredContent`, after which Claude Code is reported to drop a result's text or images; more than one text block, of which an HTTP result's first alone is reported to reach the model.
- **A failed call is the tool's result.** A call the game refuses, a name it lacks, a run on a dedicated server or a handle gone, returns `isError` with what to change, so the agent corrects itself, as MCP gives a model a call's failure; a JSON-RPC error is left to a request MCP's schema refuses.
- **A table comes in pages.** `sim_units` is concise unless the call asks for the detail, holds at most a page of rows, and a cut table says how many rows it left and which filters narrow it, as Anthropic's guide advises, under `anthropic/maxResultSizeChars`. Refused: every row at once, which a match of 1,000 units makes larger than Claude Code keeps in the conversation.
- **A handle names a game, and one game needs none.** `game_start` gives a handle that lives until its game exits, and a call of no handle takes the only game, failing with the list of games when there are more. Refused: a handle in every call, a pick the agent need not make.

### Time

- **Reads and time never enter the log.** A read takes the world between ticks, and the pace stays the local server's (08-sessions.md, The pace sets the tick rate); a dedicated server refuses a run with an error that says so.
- **A read changes nothing.** A read runs as a system of read-only parameters, so no component's change tick moves, as the checkpoint's copy trusts them (08-sessions.md, Every state write marks its component changed). Refused: a read through `World` by hand, whose mutable access a later edit can turn into a write.
- **A console's local match starts paused.** `sim_run` runs to a tick, or until a typed condition holds after a tick, a unit's probe state, a log event of a type, a script failure or the match's end, then pauses, and returns at the wall time its caller gives, 120 s unless named, under the two minutes after which Claude Code sends a call to the background, with the tick it stopped at and why; a count of ticks becomes its tick as the call starts, so a repeat runs no further. With a client, the reply waits for the client to draw the tick it paused at, so a screenshot after it shows that tick, as StarCraft II's single-step mode advances only on request. Refused: real time first, under which a read and a screenshot fall on different ticks; a step request for each tick; MCP's tasks, a beta of Claude Code reported not to work.
- **A cancel pauses the run.** A call Claude Code cancels pauses its run at the tick it reached and sends nothing more for it, as MCP's cancel asks. Refused: a run that plays on after its caller left.
- **A run plays at the pace's fastest speed.** A run plays at four times the session's rate, which the client and its local server already follow. Refused: the server's full speed, past the burst of 9 ticks a frame (08-sessions.md, A burst after a stall runs 9 ticks at most), which no measurement shows the client's timelines and link follow, planned once one does.

### The view

- **A pixel is the screenshot's.** A pixel a `view_` tool takes is one of the last image `view_screenshot` gave, which names its scale to the window's frame, the tick it drew and the camera's rig; its region is the window, a rectangle of the window's pixels or the box round units on screen, scaled down until no side passes 2,000 px and its visual tokens, `⌈width / 28⌉ × ⌈height / 28⌉`, do not pass 4,784, so Claude reads the image at its own pixels and names a point in them, as Claude gives coordinates in the image it resized, and holds each image of a request of more than 20 to no side past 2,000 px. Refused: logical pixels, which differ from the image's by the monitor's scale; the window's whole frame, whose units a 7680 × 2160 monitor shrinks below what a model reads; a lossy format, whose artifacts the vision guide warns of.
- **A capture waits one second for its frame.** A screenshot that draws no frame in 1 s, 60 frames at 60 Hz, fails with a result that says the window may be hidden, minimized or covered, as Wayland's compositors stop the frames of such a window. Refused: a wait with no bound, which holds the agent on a window it cannot see.

### Planned

- **A change is an `Admin` input of Rhai, planned.** `sim_eval` with a change logs its source as a server input, run in a role `admin` that holds the mode's calls and the admin verbs the registry lists, so a replay, the verifier and a report's replay run it again (02-engine-core.md, Everything outside is a recorded input); the session's terms say they admit admin changes, a ranked server refuses such terms, and a listing marks the session, as OpenRA's lobby option admits its dev orders and Factorio marks a save. Refused: typed admin orders, as OpenRA's 16, each a decoder beside a verb the script API holds; both, two ways to one change; writes into the world, which no log replays.
- **A read is a script of the query role, planned.** `sim_eval` with a query runs in a role `query`, whose viewer is the whole match, as a local spectator sees every unit, and enters no log.
- **An agent plays a player slot as a bot, planned.** `BotPlay::Agent` plays a player slot the host gives the agent: a script of the bot role runs at the next think, once or at each think until the agent replaces it, reading its team's view and ordering its own units (03-game-scripting.md, Bots send inputs), and the log marks the player slot a bot's; an order is such a script, so the console carries no directive. Refused: a client of its own key and no window, which the log marks a human player's, with a second host of bots in the client; both at once.
- **A player's AI calls its provider, planned.** A server's bot of a language model calls its provider's API itself and writes the scripts an agent writes, as MCP deprecates its sampling for the provider's API; no model runs in the sim, whose inputs carry what one decides. Refused: MCP between the server and a model.

## Checks

- `campfire-console`'s tests round-trip each request and reply through `codec::Json`, and its fingerprint moves with a field of either.
- A server under `--console stdio`, started as its binary, answers a status over its pipes, with the tick it read; it stops as its input closes; `campfire-mcp` refuses a game of another fingerprint, logs a stray line and reads on, and fails a call whose game exited with its exit status.
- A local server's console runs the lane match to tick 300 and pauses after it, and the state hash its status gives there is the hash the verifier's replay of the published log reaches at tick 300; a run until a unit is idle stops at the first tick its probe shows it idle; a run past its wall time and a cancelled run each pause at the tick they reached; a status asked during a run answers before it; after a run of reads, the checkpoint's copy still equals a full snapshot.
- `campfire-mcp`'s tests, through `rmcp`'s client in the same process, list its tools in one order with their hints and schemas under both MCP's revision of 2026-07-28 and that of 2025-11-25, and call a status of a server under its console; a cut table names the rows it left.
- The client's tests compute a unit's box on screen, a region's crop and its scale to both bounds, against hand-computed pixels.
- In the client, the user watches the agent start a local match of the MOBA test mode, run it to a tick, table its units and show a screenshot of one; in a local Zero Hour skirmish of bots alone, the agent finds the walkers stuck at a tick with the tools alone, no edit of the code.
