# Plan — QUIC transport

The steps of the QUIC transport's slice ([Workflow](AGENTS.md#workflow)), in order, open items only: remove a step when it is done. Each step ends with the check chain passing for the crates it touches, and a stop for review. The slice ends when the user plays it in the client. It is a proposal for review, with no place yet in [PLAN.md](PLAN.md)'s order.

The user plays a match on a server over QUIC: the client reaches the server by its address and the TLS key its listing names, and a client that pins another key ends at once, saying so. The design is [QUIC transport](docs/design/15-quic-transport.md); each step folds its rules into designs 02, 05 and 10 where they change.

1. **Q2. The binaries on QUIC** (`protocol`, `net`, `server`, `client`, `lan-check`; D2, D6, D8): `TlsKey` in place of `CertificateHash` in the pin, the client's arguments, `Listening` and the LAN check; the TLS key and the reset key derived from the server's key, and the `tls` file and its code gone; the server's socket bound before its app runs; the server's and the client's QUIC IO; WebTransport's plugins, their asserts and the rule of one plugin for each process gone; `wtransport` and Lightyear's `webtransport` feature gone; designs 02, 05 and 10. Check: a known server key gives the TLS key and the reset key that an independent HKDF computes, and two server keys give two TLS keys; a server whose port is in use exits with failure, naming the address; the LAN check passes; no crate of the tree is tokio or `aws-lc-rs`; the user plays a match on the server over QUIC.
2. **Q3. The link's end** (`quic`, `net`, `lan-check`; D10): `LinkEnd` from the IO, on the link's entity; `CloseLink` and its `AppCode`, and `net`'s `CloseCode` at each place that unlinks with text today; the closes the app's exit writes; `LinkLost` as an enum of its causes. Check: each loopback test of `quic` that ends a link asserts its `LinkEnd`, and the peer of a `CloseLink` reads its code; an app that exits ends its peers' links by `Stopped`; an endpoint given the reset key of one that stopped resets the old connection's next packet, and the peer ends by `Reset`; the LAN check's verdict refuses an impostor that ends by another cause; the client logs `WrongServerKey` against a wrong pin.
3. **Q4. The answer bound to the TLS session** (`protocol`, `quic`, `net`; D11): `ChannelBinding` from each end's exporter, in the server's spawn of a link and on the client's entity as it links, and the fixed one of in-process links; the answer over `"campfire/connect/v2" ‖ challenge ‖ binding`; design 05's step 3. Check: the two ends of a loopback link read the same binding, and two links read different ones; an answer signed over another link's binding is refused; the in-process scripted matches pass as before.
