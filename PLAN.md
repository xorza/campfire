# Plan — next steps

Open items only, in order. Remove an item when it is done. Each step ends with the check chain passing for the crates it touches, and a stop for review. Stage context: [ROADMAP.md](ROADMAP.md); design: [design/](design/).

1. **Capabilities from `kit-moba`**: split the kit into capability crates by layer, as design 04 lays out: `combat` (teams, health, attack stats and state, strikes, deaths), `control` (the control relation, of the orders kind until `character` exists; orders; the tower rule, standing in for AI), and `navigation` (move steps, destinations, movement, waypoint paths). The stand-in creep waves move to `StandInMode`, as the mode's timer. `sim` defines the engine's tick stages in place of before and after collision, and each capability puts its systems into them: the attack's chase and windup in Act, its strike in Hit, damage and deaths in Resolve. State names change from `moba.*` to each capability's. An input payload becomes a list of commands tagged by capability, an order names the units it goes to, and a unit type says whether a dead unit stays or despawns, in place of the controller deciding. Test: the kit's tests compute the same values in their new crates, a command of a capability the mode did not declare is ignored, an order to a unit its player does not control is ignored, and the stand-in match gives the same deaths in the same ticks, and its replay agrees with the live run on every hash.
2. **Rhai host** in `script`: the fixed hashing seed, operation limits, no floats, `Num` in scripts, and one hero ability from `packages/moba` run through the `abilities` cast checks, with all-or-nothing effects. Test: the ability's effect is exact; a call over its limit fails the same way in every build and changes nothing.
3. **AI scripts and projectiles**: `orders` runs AI scripts, `think` every `think_ms` rounded up to whole ticks and staggered by unit id, with the queries and orders they call; `creep_ai.rhai` and `tower_ai.rhai` from `packages/moba` replace the native tower rule, so creeps take targets and towers prefer creeps and defend heroes. In `projectiles`, ranged attacks fire a homing projectile at `projectile_speed` that strikes on arrival. Test: hand-computed think ticks and targets for both scripts, a projectile's arrival tick, a projectile whose target dies before it lands, and a log with scripted creeps and towers replays to the same hashes.
4. **Mode from its package**: the runner loads a mode package and its dependencies with the load checks of design 08, and builds the match from it in place of `StandInMode`: its capabilities, its map (lanes and structures, in a `map/` the 3v3 package does not have yet), its unit types from `units.toml`, rewritten in capability sections, with times rounded up to whole ticks, and `mode.rhai` with its timers and `spawn_wave`. The session header names the engine release tag, the mode's fingerprint and its dependencies' fingerprints; the verifier replays only a log whose release and packages it holds, checked by fingerprint. Test: a 3v3 match from the reference package replays to the same hashes, and a log that names another release, another mode fingerprint or a missing dependency is refused with its own error.
5. **Fog of war**: grid visibility per team, and each client receives only the units its team sees, through Lightyear's replication visibility. Test: an enemy outside sight is not in the client's `World`, and appears on the tick it comes into sight.
6. **LAN play**: `server` and `client` binaries over WebTransport, with the certificate hash pinned and the connect challenge of design 05, which checks the delegation's expiry against the server clock; the client signs with auxiliary randomness from the OS, which `net` lacks today. The client draws capsules, predicts its own hero and interpolates the other units. Exit: two machines play a 1v1 lane, and the log verifies on another OS.
