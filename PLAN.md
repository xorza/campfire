# Plan — current slice

The steps of the current slice ([Workflow](AGENTS.md#workflow)), in order, open items only: remove a step when it is done. Each step ends with the check chain passing for the crates it touches, and a stop for review. The slice ends when the user plays it in the client.

## Slice 1 — A Zero Hour map on screen

The user imports their install with `campfire-import`, starts `campfire-client --local` on Tournament Desert, and sees its terrain, its tiles, blends and cliffs, and its placed objects drawn with Zero Hour's models at their places and angles, from a camera that pans, zooms and turns as the original's does. Nothing moves, and no rule runs. The design is [Zero Hour](docs/design/12-zero-hour.md), the package rules of [Packages](docs/design/05-protocol-spec.md#packages) and [Game package](docs/design/03-game-scripting.md#game-package), and what the import reads is [Zero Hour research](docs/research/zero-hour.md). A step that changes a golden says why in its commit, with the number that moved.

1. **Z1. Reads at an offset** (`store`): `InputFile::read_at(path, offset, len)`, the bytes from `offset`, `len` long at most and bounded by it, with `ReadError`'s cases and one more, `Short`, for a file that ends first. Check: a scratch file's ranges read as computed by hand: from 0, from the middle, to the end, of length 0; a range past the end is `Short`; a directory is `NotFile`.
2. **Z2. The package index** (`package`; design 05): `FileIndex`, the rows of `package.index` in postcard, read and checked as design 05 says, path order, path rules and case clashes from the index alone; `PackageDir::read` reads the index and only the manifest, `data/`, `scripts/` and `locale/`, each file checked against its row as it reads it, `ContentError::Changed` for a file whose size or SHA-256 differs, and `Missing` for a listed file not there; `PackageFiles::read_file` for any other file, by the same check; a file the index does not list is never read; the walk that hashes every file goes, and the test packages' indexes are checked in. Check: each test package's fingerprint is the one it had, as the index holds the list the walk hashed, so no golden moves; a file edited after its index fails its read with its path, and only when read; an unlisted file changes nothing; the test that holds each checked-in index equal to its files fails on a stale one and writes it again under `CAMPFIRE_BLESS=1`.
3. **Z3. Maps by name** (`capabilities`, `package`, `protocol`, `runner`, `net`, `server`, `client`; design 05, 08): `MapName`, a declared name; `map/<name>/map.toml`, which `ModePackages` reads for the map the session names alone; `SessionTerms::map`, in the session id, the log's header and the offer, after the mode's fingerprint; `--map` on the server's and the client's command lines, the mode's only map when it has one; the MOBA's and the test modes' maps moved to `map/<name>/`. Check: a mode of two maps loads each by its name and refuses a third; terms that differ only in their map have other session ids; a log names its map and replays on it; the session id's bytes as computed by hand; the goldens move only where the session id enters, each said in the commit.
4. **Z4. The import's frame** (new crate `campfire-import`, `common`, `store`; D4, D7, D10): the app and its `zero_hour` module; the `.big` index; the resolution of design 12, the case-insensitive order, the first archive keeping a path, `ZH_Generals/` last, `Data/INI/INIZH.big` skipped; the game version, by the SHA-256 of the archives it reads, refused when unknown; RefPack; the writer of one package, every file and the index in path order, through `store`. Fixtures are built byte by byte by test helpers, never copied from the game. Check: a fixture install of three archives, one shadowing another, resolves each path to its archive; a RefPack stream of each command form decodes to the bytes computed by hand; an unknown version is refused with what it found; two imports of one fixture give the same bytes.
5. **Z5. Maps imported** (`campfire-import`): the `CkMp` chunks; `HeightMapData` into `map/<name>/heights.bin`, the cell of 10 units and the step of 0.625, both exact; `ObjectsList` into the map's placed units, each its template as a unit type, lowercase and checked for clashes, its position and angle, on the map's neutral team, with no body; waypoints into markers; `BlendTileData` into `client/maps/<name>/terrain.bin`, its tiles, blends, third blends, cliff indices and cliff bits, its texture classes and blended tiles; each map's name from its folder, as a declared name. Check: a fixture map of 4 × 3 cells, two objects and a waypoint imports to the heights, units and markers computed by hand; Tournament Desert, through the install check, gives 270 × 340 cells, 784 objects of 68 kinds and 28 waypoints.
6. **Z6. Textures** (`campfire-import`; design 12): KTX2 written by hand: a DDS's DXT1, DXT3 and DXT5 blocks and mip levels as BC1, BC2 and BC3; a TGA of 24 or 32 bits as RGBA8 with its mip levels, each the mean of the four texels above it, rounded half up, in integers; each texture once, by its resolved path. Check: a fixture DDS of 8 × 8 and its 3 levels, and a fixture TGA of 4 × 2 and its levels, give the KTX2 bytes computed by hand; Bevy's KTX2 loader reads both.
7. **Z7. Models** (`campfire-import`; design 12): W3D's chunks; an `HLOD`'s meshes on its hierarchy's pivots, or a mesh alone, into a `.glb`: positions, normals, the first texture stage's coordinates, triangles, the first material pass's texture and its vertex material's colours, alpha test or blend as its shader says; the JSON through `serde_json`, the binary container by hand; each object's model, the `Model` of its `W3DModelDraw`'s default condition state or its `W3DTreeDraw`'s `ModelName`, read from the resolved INI, into `client/units.toml`. Check: a fixture HLOD of two meshes on two pivots gives the vertices, placed by their pivots, computed by hand; Bevy's glTF loader reads it; the install check converts every model the INI names but the 80 no archive holds, and reports those.
8. **Z8. The package asset source** (`client`, `package`; design 12): a Bevy `AssetSource` whose reader reads through `PackageFiles::read_file` on a blocking task; Bevy's `bevy_gltf`, `ktx2` and `png` features; a unit type's `model` from `client/units.toml`, drawn at its unit's place and angle and on the terrain's height there, as the original's interpolation of the heightmap gives it; a type with no model drawn as now. Check: a fixture package's model loads through the source, and one whose bytes differ from its row fails, logged with its path; the height at a point between four cells is the one computed by hand.
9. **Z9. Terrain** (`client`; design 12): the heightmap as a mesh of cells 10 units wide, each cell's two triangles split as the original flips them; the texture classes cut into tiles, packed in an atlas at load; each cell's tile, its blend tile with its alpha pattern, horizontal, vertical, either diagonal, inverted or long, its third blend, and its cliff UVs, in one material. Check: the vertices and the split of a fixture's 4 × 3 cells as computed by hand; the alpha of each pattern at its corners and its centre as computed by hand; Tournament Desert, through the install check, draws with no cell untextured.
10. **Z10. The camera** (`client`): the original's default pitch, height and field of view from its `GameData.ini`, as the importer writes them into the package's client data; edge and key scrolling, zoom between its limits, and turning about the point in view. Check: the camera's position and look from the defaults as computed by hand; zoom stops at each limit.
11. **Z11. The rules package and the install check** (`package`, `capabilities`, `campfire-import`, `packages/zero-hour`, new check `campfire-zero-hour-check`; D7): a mode's `script` as `{ package, path }`, a dependency's script, checked at load as its own are; `source/packages/zero-hour/`, which the imported package depends on, with the mode script of a map that only stands; the imported package as the mode, of one slot, with the fewest capabilities a map that only stands needs; the check in `source/checks/`, which imports the install `GENERALSZH_DATA` names, fails when it names none, prints the fingerprint, loads Tournament Desert in a match and plays a tick. Check: a mode whose script is a dependency's loads and runs it, and one that names a dependency it lacks, or a path that dependency lacks, fails its load with what it named; the check passes on the Mac and on the Ubuntu host with the same fingerprint; the user runs the client on Tournament Desert and sees the slice's end.
